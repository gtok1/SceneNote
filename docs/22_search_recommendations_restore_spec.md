# 검색 추천 기능 복원 보완 명세

- 작성일: 2026-09-10
- 상태: 사용자 요청에 따른 구현 지시
- 적용 작업: **스마트폰 UI 사용성 개선**
- 실행 프롬프트: [23_codex_prompt_search_recommendations_restore.md](./23_codex_prompt_search_recommendations_restore.md)
- 사용자 요청: “기존에 검색쪽에 추천작품이 있었는데 다 사라졌네? 보완 명세서 작성해서 스마트폰 UI 사용성 개선 세션에 작업 요청해줘”

## 1. 목적과 문서 우선순위

**검색에서 기존 개인화 추천과 비슷한 작품 찾기를 다시 사용할 수 있게 한다. 모바일 UI 개선 결과는 유지한다.** 모바일 사용성 개선을 기존 기능 축소의 근거로 삼지 않는다.

이 요청은 사용자가 명시한 최신 범위 결정이다. 따라서 다음 기존 지시 중 **검색의 개인화·유사 작품 추천을 제외하거나 호출하지 말라는 부분**은 이 문서로 대체한다.

- 11번 문서 §1.2의 추천/유사 작품 제외, SCR-004의 추천 없는 검색 전 화면, SCR-004 AC-2 중 추천·비슷한 작품 비노출, REG-P0-037의 빈 검색 상태 추천 미호출.
- 19번 문서 §6의 추천 노출·호출 차단.
- 20번 프롬프트 §3-2, §8-6의 확장 기능 일괄 차단 중 검색 추천에 해당하는 부분.

기존 문서는 과거 결정의 기록으로 보존한다. 검색 추천 관련 테스트의 기대값은 최신 요구로 갱신하고, 변경 사유와 새 테스트 ID를 연결한다. 나머지 테스트를 삭제하거나 축소하지 않는다. 12·14번 진행 위치, 15·17번 시즌 검색·등록의 D-N 및 보안·데이터 계약은 유지한다.

이번 복원은 검색 추천과 그 동작에 필요한 연결 화면에 한정한다. 인물 탭, 리뷰, 공유, 가져오기, 홈의 인기 추천 등 모든 확장 기능을 한꺼번에 켜지 않는다. 이들 기능의 추가 복원 여부는 이번 요청에서 정하지 않는다.

## 2. 원인 확인

| 구분 | 확인한 근거 | 판단 |
|---|---|---|
| 유사 작품 추천의 최근 회귀 | 작업 diff가 `app/search.tsx`의 유사 검색 진입·route 복원·카드 `onFindSimilar`와 `src/hooks/useSimilarContent.ts`에 `EXTENDED_FEATURES_ENABLED` 조건을 추가함. 해당 상수는 false | 모바일 개선에서 추가된 확장 기능 가드로 기존 동작이 꺼짐 |
| 개인화 추천 비활성 | `app/search.tsx`의 `MVP_PERSONALIZED_RECOMMENDATIONS_ENABLED = false`가 피드 렌더링과 Query enabled를 차단 | 현재 비활성. 이 상수는 수정 전 Git HEAD에도 false여서 이번 모바일 변경에서 새로 껐다고 단정하면 안 됨 |
| 기존 구현 보존 | 개인화 카드, 12개 새로고침, 보충, 관심 없음/더 보기/요소 줄이기, quick view, 유사 추천 훅·서비스가 남아 있음 | 기능을 새로 만들기보다 기존 연결과 수명·오류 처리를 복구하는 것이 우선 |
| 문서 범위 오류 | 이전 모바일 프롬프트가 과거 MVP 제외 항목까지 적용하도록 지시했고 해당 작업은 그 지시를 실행함 | 기능 유지 의도를 반영하지 못한 지시를 이 보완 명세로 정정 |

첨부 화면은 `한자와나오키`를 입력한 **일반 검색 결과 상태**이며, 카드의 비슷한 작품 진입이 보이지 않는다. 이 화면만으로 “모든 일반 검색 결과 아래에 개인화 추천이 항상 있어야 했다”고 추정하지 않는다. 기존 `shouldShowRecommendationFeed`는 검색어가 비었을 때 개인화 추천을 표시하는 계약이다.

첨부 화면의 “일부 외부 API 결과가 표시되지 않을 수 있습니다”는 별도 partial 응답 신호다. 이 문구를 추천 비활성의 원인으로 단정하지 않는다. 구현 후 실제 응답으로 추천 서비스 상태를 따로 검증한다.

## 3. 설계 결정

### D-1. 검색 추천은 사용 가능한 기본 기능으로 복원한다

검색의 개인화 추천과 유사 작품 추천을 사용 가능하게 한다. 기능 정책이 필요하면 검색 추천 전용 정책으로 분리하고, 무관한 확장 기능의 전역 스위치에 묶지 않는다. 상수를 true로 바꾸는 것만으로 완료 처리하지 않는다.

### D-2. 개인화 추천과 일반 검색, 유사 검색은 구분한다

| 상태 | 표시 | 요청 조건 |
|---|---|---|
| 검색어가 빈 값/공백 | 검색 입력, 최근 검색어, 기존 개인화 추천 섹션과 새 추천 버튼 | 로그인·라이브러리 준비 완료·화면 활성 조건에서 추천 Query를 허용 |
| 일반 검색어 1자 | 입력 안내 | 일반 검색 API를 호출하지 않음. 개인화 결과를 해당 글자의 검색 결과로 표시하지 않음 |
| 일반 검색어 2자 이상 | 기존 작품 검색 결과, 카드별 비슷한 작품 찾기 | 기존 검색·페이지네이션 계약. 개인화 추천의 자동 추가 로딩은 비활성 |
| 카드에서 비슷한 작품 선택 | 기준 작품명, 유사도/최신/인기 정렬, 기존 유사 추천 결과·이유 | 정확한 anchor를 선택한 뒤 유사 추천 호출 |
| “도깨비 같은 드라마” 등 기존 유사 검색 문법 | 필요시 기준 작품 선택 후 유사 추천 | 기존 parser와 기준 작품 판정 재사용 |
| 검색어 지우기 | 개인화 추천 상태로 복귀 | 사용자/유형에 맞는 캐시를 우선 사용하며 중복 요청 방지 |

개인화 추천은 기존 배치 크기 12를 유지한다. 데이터 소스가 12개를 제공하지 못하면 실제 개수를 보여주며 가짜 카드로 채우지 않는다. 검색 결과의 수·종료 안내와 추천의 수·종료 안내를 섞지 않는다.

### D-3. 유사 추천 진입 경로를 모두 연결한다

- 일반 검색 결과의 자세히/갤러리 카드에서 “비슷한 작품 찾기”를 복원한다.
- 개인화 카드와 quick view의 “비슷한 작품 더 보기”를 복원한다.
- 자연어 유사 검색, 예시 검색, 최근 검색어 재실행, 기존 `mode=similar` route 재진입이 동일한 의도 해석을 사용한다.
- 원래 검색과 유사 검색 사이를 이동할 때 검색어·유형·시즌·스크롤 문맥을 잃지 않는다.
- 일반 검색어는 일반 검색으로 동작하고 유사 검색 응답이 뒤늦게 도착해 화면을 덮지 않는다.

### D-4. 기존 추천 행동과 사용자 의도를 유지한다

- 내 취향 최신 추천, 추천 이유, 새 추천 12개, 다음 배치, 카드 quick view를 유지한다.
- 라이브러리 추가 성공 시 해당 작품의 등록 상태와 추천 보충을 반영한다. 실패 시 카드를 복구하고 입력/기존 추천을 보존한다.
- 관심 없음, 비슷한 작품 더 보기, 적용 가능한 테마의 요소 줄이기를 유지한다. 피드백 실패를 성공으로 표시하지 않는다.
- 추천 제외 관리가 기존 추천 흐름에서 연결되어 있으면 해당 경로만 복원한다. 현재 서버 피드백과 기존 로컬 제외 목록이 같은 저장소라고 가정하지 말고 실제 동작을 확인한다. 숨겨진 연결 화면 때문에 표시한 버튼이 막히면 안 된다.
- 이미 등록한 작품과 제외한 작품의 처리, 시즌별 등록 판정, cursor·중복 제거 계약을 유지한다.

### D-5. 추천 실패가 검색을 막지 않는다

- 첫 로딩/캐시 갱신/실제 0건/모든 공급자 실패/일부 공급자 실패/오프라인을 구분한다.
- 새 추천 요청 실패 시 기존 카드가 있으면 유지하고 섹션 안에 재시도를 둔다.
- 추천 API 404/500 또는 관련 테이블 부재는 “추천 작품이 없습니다”로 위장하지 않는다. 추천 섹션은 오류와 재시도를 제공하며 일반 검색은 계속 가능해야 한다.
- cold start 응답은 그대로 지원하고 아직 개인화 근거가 부족하다는 기존 안내를 보인다. 신규 사용자의 라이브러리가 빈 배열이라고 전체 추천 기능을 끄지 않는다.
- 무한 로딩을 방지하는 기존 연속 조회 횟수·시간 상한을 유지한다. 숨겨진 추천 화면에서 자동 보충/노출 기록/새 배치 요청이 계속되지 않게 한다.

### D-6. 복원한 추천도 모바일 개선 기준을 따른다

- 320 폭은 1열을 기본으로 하고 360~430 폭은 카드 내용에 따라 2열 갤러리 또는 목록을 사용한다. 큰 글자에서는 열 수를 줄이거나 목록으로 전환해 조작을 보장한다.
- 새 추천·필터·카드 행동은 줄바꿈 또는 하단 시트로 배치하고 실제 터치 영역 44×44 이상을 확보한다.
- 복잡한 피드백을 작은 아이콘 여러 개에만 의존시키지 않는다. 접근성 이름과 메뉴/quick view 등 동일 행동의 명확한 진입을 제공한다.
- 복원 대상 quick view와 테마 시트도 Safe Area·내부 스크롤·닫기·포커스 이동/복귀를 검증한다.
- 기존 5개 탭, 하단 inset, Stack 뒤로, 키보드 대응, 필터 적용/취소, 시간 원문 검증과 핀 이탈 방지를 되돌리지 않는다.
- 화면 문구는 실제 동작과 일치시킨다. 비활성인 인물 검색 결과를 함께 보여준다고 안내하지 않는다.

### D-7. 추천 활성화와 서버 준비 상태를 함께 검증한다

`personalized-recommendations`는 `user_content_feedback`, `content_themes` 등에 의존한다. 11번 문서의 과거 migration 누락 경고를 현재 상태로 단정하지 말고 실제 환경을 확인한다.

- 현재 Edge Function 배포와 관련 스키마(기존 0017~0019 포함), 응답 타입, 캐시를 확인한다.
- 가능한 인증된 읽기 요청으로 개인화·유사 추천을 각각 smoke 검증한다. 현재 서비스가 노출 기록을 저장하는 부수 동작도 확인하여 시험 계정/fixture와 실제 사용자 계정을 구분한다.
- 연결된 운영 환경의 destructive 변경·일괄 배포로 우회하지 않는다. 서버 수정이 필요하면 원인과 최소 변경을 구체화하고, 실행 권한이 없는 배포는 미완료 항목으로 명확히 보고한다.
- 외부 API는 기존 Edge Function을 경유한다. 키 노출, RLS 우회, 추천 후보 전체를 contents에 bulk 저장하는 동작을 추가하지 않는다.

### D-8. 회귀 검증으로 범위 변경을 고정한다

추천 활성화 테스트를 도입해 향후 “모바일 최적화” 또는 “MVP 정리”로 검색 추천이 다시 사라지는 것을 막는다. `REG-P0-037`의 옛 기대값은 아래 SRR-01·02·17의 최신 정책으로 명시적으로 대체하고, “일반 검색어 2자 미만은 검색 API를 호출하지 않음”과 “빈 검색 화면은 추천 API를 호출할 수 있음”을 다른 요청으로 검증한다.

## 5. 전체 수용 테스트

모든 행을 테스트 또는 QA 항목으로 옮긴다. 로직은 `node:test`+`assert/strict` 순수 함수 테스트, 상호작용은 UI/통합으로 검증한다. 실제 검증하지 않은 행은 통과로 표시하지 않는다.

| ID | 조건/행동 | 기대 결과 | 방식 |
|---|---|---|---|
| SRR-01 | 로그인·라이브러리 준비 후 빈/공백 검색 진입 | 개인화 추천 섹션과 최대 12개의 실제 응답 카드 표시. 기본값 false로 차단되지 않음 | 자동+UI+통합 |

## 6. 완료 조건

1. 검색에서 개인화 추천과 비슷한 작품 찾기를 다시 사용할 수 있다.
2. 실제 사용자 요청/응답 또는 명확히 구분한 시험 데이터로 UI와 기능을 검증한다. 플래그 변경·컴파일 통과만으로 복원 완료를 선언하지 않는다.
3. 위 22개 항목, 기존 관련 테스트, `npm test`·`npm run typecheck`·`npm run lint` 결과를 별도 QA 문서로 제공한다.
4. 실제 서비스가 환경 문제로 불가능하면 코드 완료와 서비스 미복구를 구분하고 필요한 다음 작업을 보고한다.
5. 기존 모바일 개선 변경을 일괄 되돌리거나 사용자 기록을 변경하지 않는다.


## 7. 2026-09-27 후속 요청 — 원하는 장르·제작 국가

사용자 요청: 추천 제외와 별개로 검색하고 싶은 장르와 나라를 선택한다. 기존 상단 필터의 단일 선택을 추천 헤더의 **장르·국가 필터**에서도 열 수 있게 연결한다.

- 장르 1개와 제작 국가 1개(전체/한국/일본/미국/중국)를 함께 선택하면 두 조건을 모두 만족하는 작품만 표시한다. `전체`는 해당 조건만 해제한다. 선택 요약과 해제 동선을 제공한다.
- 시트는 임시 선택을 유지하고 **적용** 때 한 번 반영한다. 닫기/취소는 기존 조건을 보존하며 초기화도 적용 전에는 요청을 바꾸지 않는다. 적용 시 목록 위치와 페이지 문맥을 초기화한다.
- 빈 검색어는 선택 조건의 개인화 추천, 2자 이상은 제목 검색이다. 별도의 국가 browse로 추천 제외 설정을 우회하지 않는다. 유사 작품 찾기는 기존 별도 조건을 유지하며 시트에서 적용 범위를 알린다.
- 추천에는 기존 계정별 제외가 우선한다. 포함 장르와 제외 장르가 겹쳐도 제외를 자동 해제하지 않는다. 라이브러리에 이 포함 필터를 적용하지 않는다.
- API는 `genre`, `country`를 받는다. 서버·클라이언트가 `_shared/discoveryFilters.ts`의 장르 별칭/복합 장르와 국가 근거 판정을 공유한다. 언어·제목·포스터로 제작 국가를 추측하지 않는다.
- 개인화 추천은 제공처 조회에 포함 조건을 전달하며, 후보의 조건 확인을 키워드 보강보다 먼저 수행한다. 선택 국가가 미국/중국이면 해당 TV 작품도 조회하되 `kdrama`/`jdrama`로 잘못 표기하지 않는다. 미선택 시 기존 추천 공급 범위는 유지한다.
- 제공처에 없는 TV 장르(로맨스·공포·스릴러)는 검증한 제공처 키워드를 사용한다. 조건 확인용 공개 메타데이터는 캐시를 재사용하고 조회 예산을 둔다. 필요한 정보를 확인하지 못하면 조건을 느슨하게 풀지 않고 일부 확인 실패로 알린다.
- 포함 조건은 Query key, 공개 공급자 페이지 캐시, 추천 cursor에 포함한다. 조건 변경 시 이전 요청을 취소하고 다른 조건의 응답/커서를 섞지 않는다. 새 추천·빈자리 보충·추가 페이지에도 같은 조건을 전달한다.
- 긍정 필터는 기존 검색 UI의 메모리 상태에 보관하며 계정 설정의 영구 저장/기기 간 동기화를 새로 도입하지 않는다. 기존 계정별 추천 제외 저장은 유지한다.
- 12개 목표, 스크롤 자동 추가, 유한한 보충/시간/키워드 예산은 [30](30_recommendation_fill_and_action_consistency_fixes_spec.md)을 유지한다. 실제 조건 충족 후보가 부족할 때는 필터 변경 동선을 제공한다.

검증은 장르·국가 교집합/전체 복귀, 별칭, 미확인 국가, 제외 우선, 필터별 캐시·커서, 미국·중국 TV 분류, 영화 국가 근거, 적용/취소/목록 초기화, 후속 페이지 조건 유지로 구성한다. 실행 증거와 플랫폼별 미실행 범위는 `development_next_steps.md`의 해당 기록에서 관리한다.

## 8. 2026-09-27 후속 요청 — 다중 선택과 계정별 저장

사용자가 복수 선택과 로그인 아이디별 저장을 요청했다. 후속 확인에 따라 시각적인 체크박스 대신 텍스트 칩을 켜고 끄는 형태로 표시한다. **§7의 단일 선택·메모리 저장 항목을 아래 내용으로 대체한다.** 기존 계정 제외 우선순위와 제한된 API 조회·자동 보충 계약은 유지한다.

- 작품 유형·장르·제작 국가를 복수 선택한다. 같은 그룹은 OR, 서로 다른 그룹은 AND다. 예를 들어 코미디/미스터리와 한국/일본을 선택하면 두 나라 중 한 곳의 두 장르 중 한 장르에 해당하는 작품을 보여준다. `전체`는 해당 그룹의 제한을 없앤다. 유형 전체는 애니·드라마·영화를 포함한다.
- 선택 상태는 칩의 배경·테두리·글자색과 접근성 `checked`로 알린다. 네모/체크 아이콘이나 별도의 ON/OFF 문구는 넣지 않는다. 모바일에서 줄바꿈하며 시트의 적용/초기화 버튼을 유지한다. 목록 상태·연도·정렬은 기존 단일 선택을 보존한다.
- 적용한 필터 전체를 `profiles.search_filters` JSON에 저장한다. 기존 본인 프로필 SELECT/INSERT/UPDATE RLS를 사용하고 성공 후 화면에 적용한다. 새로고침·재로그인·다른 기기에서는 해당 계정의 저장값을 먼저 읽는다. 저장 실패 시 시트를 닫지 않고 선택값과 재시도를 유지한다. 취소는 저장하지 않는다.
- 설정 로딩 전에는 기본값으로 검색/추천하거나 저장값을 덮어쓰지 않는다. 계정 전환 때 이전 필터·검색어·결과·열린 시트를 차단하고, 늦게 도착한 이전 계정의 조회/저장 응답은 새 계정에 적용하지 않는다. 최근 검색어의 기기 저장소도 계정별로 분리하며 과거 공용 검색어를 임의 계정에 배정하지 않는다.
- 서버 요청은 `mediaTypes`, `genres`, `countries` 배열을 사용한다. 빈 배열은 전체이며 정렬·중복 제거·별칭 정규화 후 Query key/공급자 캐시/커서를 만든다. 같은 값의 선택 순서는 캐시를 바꾸지 않는다. 기존 단일 `media_type`/`genre`/`country` 요청 호환성을 유지한다.
- 제공처의 OR 문법으로 조건을 전달하고, 지원하지 않는 조합은 제한된 조회 범위에서 확인한다. 국가·장르 여러 개를 조회한 사실을 모든 국가·장르에 속한다는 메타데이터로 바꾸지 않는다. 조회 조건의 증거만 있을 때 더 좁은 선택으로 재사용하지 않는다. 여러 선택 조합만큼 무제한 호출하지 않는다.
- AniList의 미선택 조건은 GraphQL 인자와 변수에서 생략한다. 단일 국가는 `countryOfOrigin`, 복수 국가는 비어 있지 않은 `countryOfOrigin_in`만 전달한다. 실제 API에서 `countryOfOrigin_in: null`이 HTTP 500을 반환하므로 문서의 nullable 타입만 보고 null을 보내지 않는다.

검증 범위: 그룹별 복수 선택/해제/전체, OR·AND와 제외 우선, 저장 후 새로고침 복원, 취소 무저장, 저장/조회 실패와 재시도, 계정 전환 및 늦은 응답 차단, 계정별 최근 검색어, 배열 순서에 무관한 캐시/커서, 공급자 요청 조건·조회 예산, 320px 이상 시트 접근성. 실제 실행과 미실행 플랫폼은 `development_next_steps.md`에 기록한다.
