# Codex 작업 요청: 홈 "이번 주 방영" 섹션 추가 (보는 중/보고 싶음 작품 기준)

## 배경

- `scripts/backfill-content-air-date.ts`로 콘텐츠 방영일 백필 작업이 진행됐고,
  `LibraryListItem`(`src/types/library.ts`)에 `air_date`(string | null)와
  `air_year`가 이미 내려온다.
- 그러나 방영일 데이터는 현재 검색 화면(`app/search.tsx`)에서만 사용된다.
- 사용자가 추적 중인 작품의 방영 소식을 홈에서 보여주면, 이미 있는 데이터만으로
  재방문 이유(리텐션)를 만들 수 있다.

## 목표

홈에 "이번 주 방영" 섹션을 추가해, 사용자의 라이브러리 중
**보는 중(watching) 또는 보고 싶음(wishlist)** 상태이면서
방영일이 오늘 기준 -1일 ~ +7일 범위에 있는 작품을 보여준다.

## 사전 확인 (구현 전 필수)

`air_date`의 의미를 먼저 확인할 것. 다음 중 무엇인지에 따라 설계가 달라진다:

- (a) 작품 최초 방영일(first air date)만 저장 → 과거 작품은 전부 범위 밖이므로
  "신작 방영 시작" 알림 성격이 된다. 이 경우에도 섹션은 유효하나 라벨을
  "곧 방영 시작"으로 조정한다.
- (b) 최신/다음 에피소드 방영일로 갱신됨 → 의도한 "이번 주 N화 방영" 시나리오 가능.

확인 방법: `scripts/backfill-content-air-date.ts`와
`supabase/functions/_shared/externalContent.ts`에서 air_date를 어떤 필드로
채우는지 읽는다. 확인 결과를 결과 보고에 반드시 명시한다.
(b)가 아니라면 (a) 기준으로 구현하되, 다음 에피소드 방영일 추적은
이 작업 범위에서 제외하고 후속 과제로 보고서에 남긴다.

## 구현 지시

### 1. 데이터

- 새 훅 `useUpcomingAiring()` (위치: `src/hooks/useLibrary.ts` 또는 인접 신규 파일).
- 구현: `useLibrary` 데이터에서 파생 계산으로 충분하다.
  이미 로드되는 라이브러리 목록에서 필터링하고, **새 Edge Function이나 외부 API
  호출을 추가하지 않는다** (이 작업은 기존 데이터 활용이 목적).
- 필터 조건:
  - `statuses`에 `watching` 또는 `wishlist` 포함
  - `air_date`가 오늘-1일 이상, 오늘+7일 이하
- 정렬: `air_date` 오름차순.
- 날짜 비교는 KST 기준 자정 경계로 처리한다 (사용자 베이스가 한국).
  기존 유틸에 날짜 처리 함수가 있는지 `src/utils/` 먼저 확인.

### 2. UI

- 위치: 홈(`app/(tabs)/index.tsx`)에서 "최근 핀" 섹션(01 작업)과
  인기 추천 섹션 사이. 01이 미적용 상태라면 히어로 바로 아래.
- 섹션 헤더: "이번 주 방영" (사전 확인 결과 (a)라면 "곧 방영 시작").
- 카드: 가로 스크롤 행. 포스터 + 제목 + 방영일 라벨.
  - 방영일 라벨: 오늘이면 "오늘", 내일이면 "내일", 그 외 "7월 12일 (토)" 형식.
- 카드 탭 → `/content/[id]` 상세로 이동.
- 해당 작품이 0개면 섹션을 렌더링하지 않는다.
- 가로 스크롤 목록이므로 항목이 많지 않다면 `ScrollView horizontal`로 충분하나,
  기존 홈/추천 섹션의 가로 스크롤 구현 방식이 있으면 그것을 따른다.

## 범위 제외

- 푸시 알림 (후속 과제)
- 다음 에피소드 방영일을 외부 API에서 새로 가져오는 백엔드 작업
- air_date 백필 스크립트 수정

## 수용 기준 (Acceptance Criteria)

1. 방영일이 이번 주 범위인 보는 중/보고 싶음 작품이 홈 섹션에 방영일 순으로 표시된다.
2. 조건에 맞는 작품이 없으면 섹션이 보이지 않는다.
3. 오늘 방영 작품에는 "오늘" 라벨이 붙는다.
4. 추가 네트워크 요청 없이 기존 라이브러리 쿼리 데이터만 사용한다.
5. `air_date` 의미((a)/(b)) 확인 결과가 작업 보고에 포함된다.
6. `npx tsc --noEmit`, `npx eslint .` 통과.

## 검증 방법

- 라이브러리에 air_date가 이번 주인 작품이 있는 계정으로 홈 확인.
- 시스템 날짜 경계(방영일 당일/전날/8일 후) 케이스를 단위 테스트로 검증:
  날짜 필터 함수를 순수 함수로 분리해 `src/utils/`에 두고
  `*.test.ts`를 작성한다 (기존 `src/utils/timecode.test.ts` 스타일 참고).
