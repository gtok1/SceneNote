# 43. 추천 추가 중 다른 작품 오입력 방지

작성일: 2026-10-03
선행 문서: **[00 UI 규칙](00_ui_style_rules.md)**, [42 추가 지연](42_recommendation_add_latency_spec.md), [30 표시 가능 판정·보충](30_recommendation_fill_and_action_consistency_fixes_spec.md)

## 1. 문제와 확인 범위

사용자는 추천을 연속으로 추가한 뒤, 의도하지 않은 `극장판 모노노케 제3장: 뱀의 저주`가 라이브러리에 있다고 보고했다. 첨부 화면은 등록 상태를 보여주지만 당시 누른 카드·요청 로그가 없어 그 작품의 등록 원인을 확정할 수 없다.

코드에서 확인한 오입력 경로는 다음과 같다.
- `addRecommendationResult`가 `removeOptimistically`를 호출하면 카드가 즉시 사라지고 뒤 카드가 같은 클릭 위치로 이동한다. 보충을 끝에 붙이는 것만으로 이 이동을 막을 수 없다.
- `usePersonalizedRecommendations`의 기존 짧은 피드 자동 보충 효과는 캐시 항목 제거 직후 실행된다. 성공 후 `scheduleRefill` 예약만 추가하면 먼저 시작한 자동 보충과 경쟁한다.
- FlashList는 셀을 재사용한다. 추가 버튼의 누르기 시작과 클릭 완료 사이에 작품이 바뀌면 현재 콜백만으로는 다른 작품을 대상으로 삼을 수 있다.
- React 상태 Set만으로는 다음 렌더 이전 중복 이벤트를 동기적으로 잠글 수 없다. 연속 mutation의 결과는 이전 작업에서 요청별 Promise로 처리하도록 수정돼 있다.

서비스는 클릭 콜백의 `external_source`, `external_id`, 영화/TV 구분을 `add-to-library`에 전달한다. 이 조사에서 모노노케의 실제 요청 ID·당시 운영 코드·DB 로그는 확인하지 않았다. 사용자 기록을 임의로 삭제하지 않는다.

## 2. 설계 결정

- D-1. 사용자 최신 오입력 방지 요청에 따라 **42의 즉시 카드 제거 표시 계약을 이 부분에 한해 대체**한다. 데이터 캐시에서는 제거하되 화면은 클릭한 카드의 스냅샷·인덱스를 보존한다. 추가 중에는 `추가 중`, 성공하면 `추가됨`으로 비활성화하고 다음 카드가 그 자리에 들어오지 않게 한다. 실패하면 보존 슬롯을 제거하고 기존 복원 기능을 쓴다.
- D-2. 성공한 슬롯은 현재 계정·추천 조건에서 유지하고, 명시적 새 추천 성공 시 해제한다. 필터·유형·제외 조건·계정 변경 시 이전 슬롯은 표시하지 않는다. 보충은 여전히 목록 끝에 붙인다. 슬롯은 등록 작품을 새 추천 후보로 재사용하는 것이 아니며, 서버/훅의 표시 가능 수·제외·중복 판정은 보존한다.
- D-3. 추가 진행 또는 800ms 예약 대기 동안 기존 자동 보충을 보류한다. 예약 발화 시 다른 추가/피드 요청이 진행 중이면 재예약한다. 기존 6회·45초·무진전 3회 한도는 변경하지 않는다. 다른 훅 호출자는 새 옵션을 생략하면 기존 동작이다.
- D-4. 갤러리·목록 추가 버튼은 `onPressIn`의 canonical identity와 `onPress`의 identity가 달라지면 추가하지 않는다. 키보드·접근성의 직접 활성화는 허용한다. 동일 작품의 요청은 렌더 이전에도 동기 잠금으로 한 번만 시작하며 다른 작품 추가는 허용한다.
- D-5. 성공 토스트에 요청한 작품 제목을 포함한다. 실패는 기존 고정 한국어 문구. 다른 계정/조건으로 이동한 뒤 도착한 응답은 새 문맥의 슬롯·추가됨 표시를 변경하지 않는다. FlashList `extraData`에도 추천 추가 완료 키를 포함한다.
- D-6. 서버/DB 계약·미커밋 취향 레인·보러가기 작업은 변경하지 않는다. 기존 등록 데이터 자동 정리는 범위 밖이다.

## 3. 구현 계약

`src/utils/recommendationAddFlow.ts`에 순수 함수를 추가한다.
- `retainRecommendationAddSlots<T extends { canonical_id: string }>(items, retained)`는 retained identity의 중복을 제거하고 저장된 인덱스 순서로 해당 스냅샷을 삽입한다. 입력 배열은 수정하지 않는다.
- `createRecommendationPressGuard()`는 `begin(identity)`와 `consume(identity)`를 제공한다. 시작 identity가 다른 경우 false, 동일하거나 포인터 시작 없는 접근성 활성화면 true. consume 뒤 시작 identity는 해제한다.
- `createRecommendationAddLock()`은 `claim(identity)` 성공/실패와 `release(identity)`를 제공한다.
- `shouldDeferRecommendationRefill({ additionsInFlight, scheduled })`은 두 값의 OR다.

검색 화면은 슬롯 문맥을 계정·유형·정규화 발견 필터·제외 설정으로 구분한다. 사용자별 동기 잠금을 요청 종료 시 해제한다. 기존 검색 결과 `addResult`·`getSearchAddState`는 변경하지 않는다.

## 5. 범위와 기각한 대안

변경: 검색 화면·추천 훅·추가 흐름 유틸/테스트·추천 갤러리/목록 카드, 이 명세·문서 목차·AGENTS 진입점·작업 재개 증거.

확인 창을 매번 띄우기나 전체 카드 잠금은 연속 추가 경험을 해친다. 보충만 끝에 붙이면 삭제로 당겨지는 기존 카드의 오입력 경로가 남는다. 특정 작품 자동 삭제는 당시 클릭 증거가 없고 사용자 기록을 손상할 수 있어 하지 않는다.

서버 배포·DB 변경 없음. 인증된 실제 화면/네이티브 및 당시 등록 경위 확인은 별도 후속 검증이다.
