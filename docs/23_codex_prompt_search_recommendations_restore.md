# 검색 추천 기능 복원 — 스마트폰 UI 사용성 개선 작업용 프롬프트

사용자가 검색에 있던 추천 작품이 사라졌다고 명시적으로 지적했다. **기존 모바일 UI 개선을 보존하면서 검색의 개인화 추천과 비슷한 작품 찾기를 복원하고 검증해라.** 이 문서는 분석 요청이 아니라 기존 작업에 대한 후속 구현 요청이다.

## 우선 읽을 문서와 범위

- `AGENTS.md`
- `docs/22_search_recommendations_restore_spec.md` — 이 후속 작업의 최신 범위 결정
- `docs/11_screen_implementation_spec.md`의 검색/공통 UI 및 `docs/19_mobile_usability_spec.md`, `docs/20_codex_prompt_mobile_usability.md`, `docs/21_mobile_usability_qa_2026-09-09.md`
- 검색·시즌 관련 `docs/15_season_search_spec.md`~`docs/18_codex_prompt_season_library_tracking.md`

사용자가 검색 추천 복원을 요청했으므로 11·19·20번 문서의 **검색 추천 제외 지시**는 22번 문서에 따라 대체한다. 이를 충돌로 취급해 추천을 계속 끄거나 재승인을 요청하지 마라. 나머지 설계 결정, 진행 위치/시즌 계약, 보안 조건은 유지한다.

기존 작업의 미커밋 변경이 같은 `/Users/youngilkim/SceneNote`에 남아 있다. 전체 revert/reset, 파일 덮어쓰기, 미관련 작업 삭제 없이 현재 구현 위에 필요한 부분만 수정해라. 새 task를 만들 필요 없이 이 작업에서 계속 진행한다.

## 확인된 원인

1. `src/constants/features.ts`의 `EXTENDED_FEATURES_ENABLED = false`가 최근 변경에서 유사 검색 진입, 카드 `onFindSimilar`, route 복원, `useSimilarContent`의 요청을 차단했다.
2. `app/search.tsx`의 `MVP_PERSONALIZED_RECOMMENDATIONS_ENABLED = false`도 빈 검색 화면의 개인화 추천을 차단한다. 이 값은 모바일 개선 전 Git HEAD에도 false였다. 개인화까지 이번 diff에서 새로 제거했다고 보고하지 마라.
3. 추천 컴포넌트·서비스·피드백·보충 로직은 남아 있다. 기존 연결을 복원하는 작은 변경을 우선해라.
4. 사용자의 화면은 `한자와나오키` 일반 검색 결과다. 일반 검색 중에는 카드의 비슷한 작품 진입을 제공하고, 개인화 추천은 기존 계약대로 빈 검색 화면에서 제공해라. 모든 일반 검색 결과에 개인화 목록을 새로 붙이는 작업으로 범위를 넓히지 마라.

## 구현 요구

1. **검색 추천 정책을 분리해라.** 개인화·유사 추천을 복원하기 위해 전역 확장 기능을 true로 바꾸어 인물·리뷰·공유·가져오기까지 켜지 마라. 검색 추천에 필요한 가드와 연결 화면만 다룬다.
2. **빈 검색 상태의 개인화 추천을 복원해라.** 기존 내 취향 최신 추천, 최대 12개 배치, 새 추천/다음 배치, 추천 이유, quick view, 관심 없음/더 보기/요소 줄이기, 추가 후 보충을 다시 사용할 수 있게 한다. 신규 사용자는 기존 cold_start 응답을 지원한다.
3. **유사 추천을 모든 기존 경로에서 복원해라.** 자세히/갤러리 카드, 개인화 카드, quick view, 자연어 질의, 예시, 최근 검색어, mode=similar route를 확인한다. 현재 `searchFromHistory`는 query/history만 설정하므로 유사 검색 의도가 올바로 실행되는지 함께 고쳐라.
4. **기존 검색을 보존해라.** 일반 검색의 2자 조건, 필터 적용/취소, 시즌별 카드 key, 등록 배지, 다음 페이지, partial 안내와 상세 복귀를 유지한다. 빈 검색의 추천 요청은 2자 미만 일반 검색 요청 금지와 다른 계약이다.
5. **요청 수명을 처리해라.** 개인화 훅의 enabled만 바꾸지 말고 자동 보충/무한 스크롤/노출 기록/진행 요청도 모드·인증·화면 활성 상태를 따른다. 늦은 응답이 새 검색 결과를 덮거나 탭 이탈 뒤 계속 호출되지 않게 한다.
6. **부분 실패를 정확히 표시해라.** 실제 0건, 일부 공급자 실패, 404/500, 타임아웃, 오프라인을 구분한다. 추천이 실패해도 일반 검색은 동작하고, 캐시가 있으면 유지하며 재시도를 제공한다. 12개 미만이면 실제 개수를 표시한다.
7. **복원된 영역에도 모바일 개선을 적용해라.** 320/360/390/430 폭, 실제 터치 영역 44 이상, 큰 글자, 시트 Safe Area·스크롤·포커스 복귀를 검사한다. 기존 메뉴·키보드·필터·뒤로·핀 검증을 되돌리지 마라.
8. **backend 준비 상태를 확인해라.** personalized-recommendations/similar-content의 실제 응답, 관련 스키마와 기존 0017~0019 적용 여부를 가능한 권한 안에서 확인한다. 키 출력이나 RLS 우회, 무관한 일괄 배포 없이 최소 원인 수정을 준비한다. 실제 사용자 피드백/라이브러리를 시험 목적으로 임의 변경하지 마라.
9. **추천과 연결된 제외 관리가 막혔는지 확인해라.** 실제 기존 흐름에서 쓰는 경로만 복원하고 로컬 제외 저장소와 서버 feedback을 임의로 통합하지 마라. 표시한 버튼은 끝까지 동작해야 한다.

## 검증 및 완료 보고

- 22번 명세의 **SRR-01~SRR-22 전체 행**을 자동 테스트 또는 UI/통합 QA로 옮긴다. 순수 함수 테스트에서 React Native/Supabase 모듈을 import하지 않는다.
- `REG-P0-037` 등 기존 추천 미호출 기대는 최신 명세에 맞게 수정하되 ID와 변경 사유를 추적한다. 나머지 기존 테스트는 축소하지 않는다.
- `npm test`, `npm run typecheck`, `npm run lint`를 실행하고 변경 관련 실패를 수정한다.
- 8081 기존 웹 서버를 우선 사용한다. 재기동이 필요하면 `npm run web -- --port 8081 --localhost --clear`를 사용하며 다른 포트를 만들지 않는다.
- 로그인한 검색 화면의 빈 검색 추천, `한자와나오키` 결과의 비슷한 작품 진입, 유사 추천 결과를 실제로 확인한다. 사용자에게 제공할 수 있으면 변경 후 화면을 남긴다.
- 로그인·실기기·배포 접근 부족은 미검증/미복구로 명시한다. flags 활성화와 컴파일 통과를 서비스 복구 완료라고 보고하지 않는다.
- 새 QA 파일에 각 테스트의 통과/실패/미검증, 원인, 변경 파일, 서버 상태를 기록한다. 기존 모바일 QA 문서는 덮어쓰지 마라.
