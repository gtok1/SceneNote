## 웹 실측

로그인 화면: 320×568, 360×800, 390×844, 430×932, 844×390, 767×800, 768×800, 1199×800, 1200×800 확인. 이메일·비밀번호 입력이 가로 화면 경계 내에 있으며 보조 링크 3개는 모두 높이 48px이었다. 320×568에서 스크롤 후 마지막 링크 bottom=544px, 844×390에서 bottom=366px로 화면 안에 도달했다. 빈 폼 제출 뒤 오류를 표시하고 `document.activeElement`의 접근성 이름이 `이메일`인 것을 확인했다. 회원가입 320×568에서도 빈 폼 제출 후 alert 오류와 이메일 첫 포커스를 확인했다. 인증 성공 요청은 실행하지 않았다.

글자 200%, 인증 이후 모든 화면, iOS/Android 키보드·Safe Area·스크린 리더는 미검증이다. 웹 인증 화면 확인을 네이티브 또는 인증 이후 화면 통과로 확장하지 않는다. 동일 크기의 변경 전 화면을 이 작업에서 캡처하지 않아 전후 비교 이미지는 제공하지 않는다.

## 기존 계약과 남은 제한

- 12·14의 NULL/0, 수동값 우선, 시즌 상대 회차, 체크 재동기화, 저장 버튼 확정과 상태 제안을 유지했다. 진행 상태의 단일 status/status_flags 통합은 11의 OPEN-010이 미결정이므로 데이터 의미를 바꾸지 않았다.
- 15·17의 AniList 별도 작품/TMDB 시즌 모델, 기존 NULL 항목, 시즌별 등록 매칭을 유지했다. 어댑터·DB 스키마·RLS·외부 키를 변경하지 않았다.
- 신규 공유/인물/추천/리뷰/가져오기를 가드했고 기존 공개 링크 회수 정책(OPEN-011)은 변경하지 않았다.
- 저장 직전 최신 작품/episode 소속과 duration을 DB에서 조회한다. 조회 오류를 ‘길이 없음’으로 처리하지 않는다. 영화용 더미 회차를 생성하지 않는다.
- 기존 `services/pins.ts`는 본문 INSERT/UPDATE와 태그 저장이 별도 요청이다. 이번 UI 범위에서는 RPC/DB 재설계를 하지 않았으므로, 태그 단계 실패 또는 응답 유실 후 재시도의 원자성·중복 방지(REG-P0-036, MU-14/18)는 미해결 기존 제한이다. 동시 연속 탭 차단을 이 문제 전체의 해결로 주장하지 않는다.
- 인증된 회차 목록 200개, 긴 제목/포스터 없음, 메모 500자, 여러 시즌, 실패/오프라인, 삭제 rollback은 실데이터 UI로 확인하지 않았다. 순수 함수 회귀 통과만으로 이들을 통과 처리하지 않는다.
- 이번 구현을 위해 기존 D-N 결정을 변경할 필요는 없었다.

| I-3 | 기존 NULL 행 보유 상태에서 시즌2 추가 | NULL 행과 시즌2 행이 **공존** (충돌 없음) |




## 구현 참고

- React Native 0.81의 [KeyboardAvoidingView](https://reactnative.dev/docs/0.81/keyboardavoidingview) 문서에 따라 iOS에 header offset을 지정했다. Android는 OS resize를 명시하고 별도 padding 회피를 중복 적용하지 않았다. 실제 OS 키보드 검증은 남아 있다.
- 주요 조작의 48 기준은 [Android 접근성 문서](https://developer.android.com/guide/topics/ui/accessibility/views/apps-views?hl=en)를 참고했다. 웹 px 실측을 네이티브 dp 실측으로 간주하지 않는다.
