# Codex 작업 요청: 프로필 통계 개선 — 오표기 수정, 감상 연도 정확화, 타입별 분포, 취향 리포트 공유

## 배경 (제품 컨셉)

SceneNote의 핵심 목적은 "내가 본 작품들을 상대방과 소통하고 공유하는 수단"이다.
프로필 통계는 이 컨셉에서 **내 감상 취향을 한눈에 보여주는 명함** 역할을 해야 하는데,
현재는 정확성 문제와 표현력 부족으로 그 역할을 못 하고 있다.

현재 프로필 화면(`app/(tabs)/profile.tsx`) 구성:
1. 이메일 카드
2. 요약 통계 4칸 (등록 작품 / 완료 / 핀 / 태그) — `useLibraryStats()`
3. 연도별 감상 통계 — `src/components/stats/YearStatsSection.tsx`
4. 장르 통계 (도넛/막대/랭킹 3페이지 스와이프) — `src/components/stats/GenreStatsSection.tsx`

확인된 문제 (실사용 스크린샷 + 코드 기준):
- **문제 1 (오표기)**: 장르 섹션 상단 "총 1127개 작품 등록됨" — 실제 등록 작품은 458개.
  `GenreStatsSection.tsx`의 `totalCount`가 장르별 count 합산인데(작품 1개가 장르 여러 개 보유),
  라벨이 "작품 등록됨"이라 명백히 틀린 숫자로 보인다. 도넛 중앙 "1127 작품"도 동일.
- **문제 2 (왜곡)**: 연도별 통계 "기록" 모드가 `updated_at` 기준
  (`YearStatsSection.tsx`의 `yearFromDate(item.updated_at)`)이라,
  Netflix 대량 등록 이후 447개 작품이 전부 "2026년" 한 줄에 몰려 차트가 무의미하다.
  실제 감상일 데이터는 DB에 없다 — 대량 등록 엑셀에는 `first_watched_date`/
  `last_watched_date` 컬럼이 있었으나(`src/types/bulkImport.ts`),
  `bulk-register-netflix` Edge Function이 이를 저장하지 않았다(코드에서 미사용 확인됨).
- **문제 3 (표현력 부족)**: "애니 vs 한드 vs 일드 vs 영화" 타입별 분포가 없다.
  소통 컨셉에서 "나는 일드 위주로 본다" 같은 취향 정체성 표현의 기본 축인데 빠져 있다.
- **문제 4 (공유 불가)**: 통계를 이미지로 공유할 수단이 없다.

아래 작업 A~D로 나눈다. A, B는 정확성 수정이므로 먼저 진행한다.

## 작업 A. 장르 통계 오표기 수정

### 구현 지시

1. `GenreStatsSection.tsx`에서 두 숫자를 분리한다:
   - **실제 작품 수**: `useLibrary("all")` 또는 `useLibraryStats()`의 등록 작품 수를 사용.
   - **장르 집계 합**: 도넛 세그먼트 값으로만 사용하고 사용자에게 "작품 수"로 표시하지 않는다.
2. 상단 라벨을 "총 458개 작품 · 장르 기준 분포"처럼 실제 작품 수 기준으로 바꾼다.
3. 도넛 중앙도 실제 작품 수 + "작품" 라벨로 교체한다.
4. 도넛/막대/랭킹의 각 장르 count는 "이 장르를 가진 작품 수"이므로 그대로 두되,
   비율(%) 표기를 쓸 경우 분모를 무엇으로 할지 주석으로 명시한다
   (권장: 장르 count 합 대비 % — 세그먼트 합계 100%가 유지되도록).

### 수용 기준

1. 프로필의 어떤 위치에도 장르 합산 수치가 "작품 N개"로 표시되지 않는다.
2. 등록 작품 458개 계정에서 상단 라벨과 도넛 중앙이 458을 표시한다.

## 작업 B. 연도별 감상 통계 정확화 (감상일 컬럼 도입)

### 방향

"기록" 모드가 의미를 가지려면 실제 감상 시점이 필요하다. `updated_at`은
상태 변경/대량 등록 시점일 뿐이다. 감상일 컬럼을 도입하고, 없으면 명확히
fallback 규칙을 적용한다.

### 구현 지시

1. **마이그레이션**: `user_library_items`에 컬럼 추가
   (`supabase/migrations/` 번호 체계를 따라 신규 파일):
   - `first_watched_at DATE NULL` — 처음 본 날(또는 연도만 알면 해당 연도 1월 1일)
   - `last_watched_at DATE NULL` — 마지막으로 본 날
   - COMMENT로 의미와 "연도만 아는 경우 1월 1일로 저장" 규칙을 남긴다.
   - RLS 변경은 불필요(기존 행 단위 정책이 컬럼을 커버하는지 확인만).
2. **연도 통계 로직 수정** (`YearStatsSection.tsx`의 `createYearStats`):
   - "기록" 모드: `last_watched_at` 연도 사용. 없으면 그 항목은 "감상일 미상"
     버킷으로 분리해 차트 하단에 "감상일 미상 N개"로 표시 (updated_at으로
     추정하지 않는다 — 왜곡의 원인이므로).
   - "방영" 모드: 기존 유지 (`air_year`).
   - 기본 선택 모드: 감상일 데이터가 있는 항목이 10개 미만이면 "방영"을
     기본으로 보여준다 (현재 데이터 상태에서 첫 화면이 무의미해지는 것 방지).
3. **감상일 입력 수단** (최소 범위):
   - 콘텐츠 상세의 리뷰/상태 편집 UI(`src/components/content/ContentReviewEditor.tsx`
     구조 확인)에 "본 시기" 입력(연도 필수, 월/일 선택)을 추가한다.
     `src/components/common/YearSelect.tsx`가 이미 있으므로 재사용.
   - 저장은 기존 라이브러리 업데이트 mutation 경로에 필드 추가.
4. **대량 등록 경로 보완**:
   - `bulk-register-netflix` Edge Function과 클라이언트 요청 페이로드에
     `first_watched_date`/`last_watched_date` 전달·저장을 추가한다
     (엑셀에 이미 있는 데이터를 버리지 않기).
   - 기존 458개 데이터의 감상일 백필은 이 작업 범위에서 제외하되,
     "동일 엑셀 재실행 시 감상일만 업데이트(upsert)되도록" idempotent하게
     만들어 재실행 백필이 가능한 구조로 한다. 이 재실행 절차를 결과 보고에 적는다.

### 수용 기준

1. 감상일이 있는 항목은 해당 연도에, 없는 항목은 "감상일 미상"으로 집계된다.
   updated_at 기준 집계 코드가 제거된다.
2. 콘텐츠 상세에서 본 시기를 입력하면 연도별 통계에 즉시 반영된다.
3. 대량 등록을 재실행하면 기존 항목의 감상일이 채워지고 중복 행이 생기지 않는다.
4. `npx tsc --noEmit`, `npx eslint .`, 마이그레이션 `npx supabase db push` 통과.

## 작업 C. 요약 통계 재구성 + 타입별 분포 추가

### 구현 지시

1. **요약 카드 재구성** (`profile.tsx` 상단 4칸):
   - 현재: 등록 작품 / 완료 / 핀 / 태그 — 태그 카드는 정보 가치가 낮다.
   - 변경: 등록 작품 / 완료 / 핀 / **올해 본 작품**(작업 B의 감상일 기준,
     없으면 올해 등록 기준으로 fallback하고 라벨을 "올해 등록"으로).
   - 웹 와이드에서 2×2 거대 카드로 퍼지는 현재 레이아웃을 4열 콤팩트로 조정
     (기존 `YearStatsSection`의 `summaryItem` 스타일 참고).
2. **타입별 분포 섹션 신규**: `src/components/stats/TypeStatsSection.tsx`
   - 데이터: `useLibrary("all")`에서 `content_type`별 집계 (파생 계산, 신규 쿼리 불필요).
   - 타입 라벨은 라이브러리 탭 필터와 동일한 분류(애니/한국 드라마/일본 드라마/영화/기타)를
     사용한다 — `src/constants/status.ts`와 `src/utils/libraryFilters.ts`에서
     기존 매핑을 찾아 재사용하고, 새 매핑을 만들지 않는다.
   - UI: 가로 스택바(비율) + 타입별 개수 목록. 도넛보다 비교가 쉬운 형태 권장.
   - 위치: 요약 카드 아래, 연도별 통계 위.
   - 타입 색상은 `GENRE_COLORS`가 아닌 고정 팔레트를 `src/constants/`에 정의
     (타입은 5종 고정이므로 항상 같은 색 — 공유 카드에서도 재사용).

### 수용 기준

1. 프로필에서 애니/한드/일드/영화/기타 비율을 한눈에 볼 수 있다.
2. 타입 분류가 라이브러리 탭 필터와 동일한 기준으로 집계된다.
3. 데스크톱 폭에서 요약 카드가 과도하게 크지 않다.

## 작업 D. 취향 리포트 공유 카드 ("내 감상 취향 공유")

### 배경

소통 컨셉의 직접 구현체. 프로필 통계를 이미지 카드 1장으로 만들어
공유 시트로 내보낸다. `04_핀_공유_카드.md`와 같은 기술 기반
(`react-native-view-shot` 캡처 + `expo-sharing`)을 사용한다 —
04가 먼저 구현됐다면 캡처/공유 유틸을 공용 모듈로 추출해 재사용한다.

### 구현 지시

1. 신규 컴포넌트 `src/components/stats/TasteReportCard.tsx` (4:5 비율, 1080×1350):
   - 헤더: "OOO의 감상 기록" (표시 이름이 없으므로 이메일 @ 앞부분 사용) + SceneNote 워드마크
   - 핵심 수치: 총 작품 수, 완료 수, 핀 수
   - 타입별 분포 스택바 (작업 C의 고정 팔레트 재사용)
   - 장르 Top 3 (작업 A의 정확한 집계 기준)
   - 올해 본 작품 수 (작업 B 감상일 기준, 미상이면 생략)
   - 포스터 이미지는 넣지 않는다 (외부 API 이미지 재배포 라이선스 불확실 — 04와 동일 정책)
2. 진입점: 프로필 화면 상단 이메일 카드 근처에 "취향 카드 공유" 버튼.
3. 개인정보: 카드에 이메일 전체 주소를 넣지 않는다 (@ 앞부분만).
   생성 전 미리보기 모달을 띄워 사용자가 내용을 확인하고 공유하게 한다.
4. 통계 0건(신규 계정)이면 버튼을 비활성화하고 안내 문구를 표시한다.

### 수용 기준

1. 프로필에서 버튼 탭 → 미리보기 → 공유 시트로 카드 이미지가 공유된다.
2. 카드에 이메일 도메인이 노출되지 않는다.
3. 작품 0개 계정에서 버튼이 비활성 상태이며 크래시가 없다.
4. 카드의 수치가 프로필 화면 표시 수치와 일치한다.

## 진행 순서 및 공통 사항

- 순서: A → B → C → D (D는 C의 타입 분포와 A의 장르 집계를 카드에 재사용).
- A~D 각각 별도 커밋, 커밋 메시지에 작업 문자 명시.
- 통계 수치가 서로 모순되지 않는 것이 이 작업 전체의 핵심 품질 기준이다.
  완료 후 한 계정에서 요약 카드 / 연도별 / 타입별 / 장르 / 공유 카드의
  수치를 교차 대조한 결과를 보고에 표로 포함할 것.
- `npx tsc --noEmit`, `npx eslint .` 통과.
