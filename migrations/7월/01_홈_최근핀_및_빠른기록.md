# Codex 작업 요청: 홈 화면에 "최근 핀" 섹션 추가 + 보는 중 카드에서 핀 빠른 작성

## 배경

- SceneNote의 핵심 목적은 "내가 본 작품을 상대방과 소통·공유하는 수단"이다
  (00 개요의 제품 컨셉 참고). 공유할 거리는 기록에서 나오므로, 기록이 꾸준히
  쌓이게 만드는 것이 이 작업의 목적이다.
- 현재 홈(`app/(tabs)/index.tsx`)은 히어로 배너 → 인기 추천
  (`PopularRecommendationSection`) → 보는 중 목록 구조로, 사용자 자신의 기록
  (최근 남긴 핀·메모)이 홈에 전혀 보이지 않는다. 내 기록이 보여야 "이어서
  기록하고, 공유하고 싶다"는 동기가 생긴다.
- 핀 작성 진입도 현재 콘텐츠 상세 → 에피소드 목록 → 핀 추가로 3단계라서
  "시청 중 실시간 기록" 시나리오의 마찰이 크다.

## 목표

1. 홈에 "최근 핀" 섹션을 추가해 마지막으로 기록한 핀 3개를 보여준다.
2. 홈의 보는 중 카드에서 1탭으로 핀 작성 화면(`/pins/new`)에 진입할 수 있게 한다.

## 현재 코드 상황 (반드시 참고)

- `app/(tabs)/index.tsx`: `useLibrary("watching")`으로 보는 중 목록을 가져와
  `ContentGalleryCard`로 그리드 렌더링. `SectionHeader` 컴포넌트가 이미 파일 내에 있다.
- `src/hooks/useTimelinePins.ts`의 `useAllPins()`: 사용자의 전체 핀을 반환.
  `TimelinePin` 타입(`src/types/pins.ts`)에 `content_title`, `episode_number`,
  `display_time_label`, `memo`, `emotion`, `is_spoiler`, `created_at` 포함.
- 핀 목록 아이템 컴포넌트로 `src/components/pins/PinTimelineItem.tsx`가 이미 존재한다.
  재사용 가능한지 먼저 확인하고, 홈용으로 과하면 경량 카드를 새로 만든다.
- 핀 상세 라우트: `/pins/[id]`. 핀 작성 라우트: `/pins/new`
  (params: `contentId`, `episodeId`(선택), `duration`(선택)).
- 스포일러 처리: `src/atoms/spoilerAtom.ts`의 `revealedSpoilerPinIdsAtom` 참고.
  핀 탭(`app/(tabs)/pins.tsx`)의 기존 스포일러 블러/토글 패턴을 따른다.

## 구현 지시

### 1. "최근 핀" 섹션

- 위치: 히어로 배너 바로 아래, `PopularRecommendationSection` 위.
  (외부 추천보다 사용자 자신의 기록이 먼저 보이는 "내 기록 중심 홈"이 목적)
- 데이터: `useAllPins()` 결과를 `created_at` 내림차순으로 정렬해 상위 3개.
  이미 정렬돼 오는지 훅 구현을 확인하고 중복 정렬하지 않는다.
- 각 카드 표시 항목: 작품 제목, 에피소드 번호(있으면 "N화"), 타임코드
  (`display_time_label`), 메모 1줄(ellipsis), 감정 뱃지(있으면).
- `is_spoiler === true`인 핀은 메모를 블러/마스킹 처리하고 탭하면 공개
  (기존 핀 탭 패턴 재사용).
- 카드 탭 → `/pins/[id]` 이동.
- 섹션 헤더는 기존 `SectionHeader` 재사용: 제목 "최근 핀", 액션 "전체 보기" → `/pins` 탭 이동.
- 핀이 0개면 섹션 자체를 렌더링하지 않는다 (빈 상태 카드로 공간 차지하지 말 것).
- 새 컴포넌트를 만들 경우 `src/components/pins/RecentPinCard.tsx`로 배치.

### 2. 보는 중 카드에서 핀 빠른 작성

- `ContentGalleryCard`(`src/components/content/ContentGalleryCard.tsx`)에
  선택적(optional) `onAddPin` prop을 추가한다. 기존 사용처(라이브러리 등)가
  깨지지 않도록 prop이 없으면 지금과 동일하게 렌더링돼야 한다.
- 홈의 보는 중 카드에서만 `onAddPin`을 전달한다.
- UI: 카드 하단 또는 우상단에 작은 핀 아이콘 버튼(`Ionicons` 사용, 프로젝트에 이미 도입됨).
  포스터 탭(상세 이동)과 터치 영역이 겹치지 않게 한다. `accessibilityRole="button"`,
  `accessibilityLabel="핀 추가"` 필수.
- 동작: `/pins/new`로 push, params는 `contentId`만 전달
  (에피소드는 핀 작성 화면에서 선택 가능해야 함 — `app/pins/new.tsx`가
  episodeId 없이 동작하는지 확인하고, 안 되면 그 처리를 이 작업 범위에 포함).

## 범위 제외

- 핀 작성 화면 자체의 UX 개선 (별도 작업)
- 홈 인기 추천 섹션 변경
- 백엔드/스키마 변경 (이 작업은 순수 프론트엔드)

## 수용 기준 (Acceptance Criteria)

1. 핀이 1개 이상인 사용자는 홈 진입 시 최근 핀 최대 3개를 본다.
2. 핀이 0개인 사용자의 홈은 기존과 시각적으로 동일하다(섹션 미노출).
3. 스포일러 핀의 메모는 기본적으로 가려져 있고, 탭하면 공개된다.
4. 홈 보는 중 카드의 핀 버튼 탭 → 해당 작품이 선택된 상태의 핀 작성 화면이 열린다.
5. 라이브러리 등 `ContentGalleryCard`의 기존 사용처는 UI/동작 변화가 없다.
6. `npx tsc --noEmit`, `npx eslint .` 통과.

## 검증 방법

- `npx expo start` 후 웹/모바일에서 홈 확인.
- 핀 0개 계정(또는 데이터 삭제 후) 홈에서 섹션이 사라지는지 확인.
- 좁은 화면(width < 700)에서 최근 핀 카드 레이아웃이 깨지지 않는지 확인.
