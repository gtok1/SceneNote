# SceneNote 스마트폰 사용성 분석 및 개선 제안

- 작성일: 2026-09-09
- 분석 기준: Git `fb07e3c`의 화면 코드와 기존 명세
- 상태: **구현 전 개선 제안**. 기존 명세의 설계 결정(D-N)을 대체하지 않는다.
- 실행 지시문: [20_codex_prompt_mobile_usability.md](./20_codex_prompt_mobile_usability.md)

## 1. 판단

**모바일 대응의 기반은 있으나, 스마트폰에서 편하게 기록하는 앱이라고 평가하기에는 핵심 동선의 보완이 필요하다.** 우선순위는 하단 메뉴와 돌아가기 → 입력 정확성·키보드 → 핀 기록·조회 → 정보 밀도 순이다.

라이브러리의 모바일 필터 시트, 작은 화면의 단일 열 핀 목록, 진행 위치 직접 입력은 잘 마련되어 있다. 반면 전역 하단 메뉴의 고정 최소 너비, 일부 Stack 화면의 뒤로 버튼 부재, 키보드 대응 누락, 핀 작성·상세의 컨텍스트 부족은 사용자가 매번 겪는 문제다. 추천·인물·리뷰가 핵심 기록 행동보다 많은 공간을 차지하는 구조도 기존 MVP 목표와 맞지 않는다.

사용자 테스트를 진행한 것은 아니므로 점수나 작업 완료 시간을 임의로 산출하지 않았다.

## 2. 확인 범위와 한계

| 방법 | 실제 확인한 내용 | 한계 |
|---|---|---|
| 정적 코드 분석 | 라우팅, 홈, 라이브러리, 검색, 콘텐츠 상세, 에피소드, 핀 생성·상세, 인증, 공통 컴포넌트 | 렌더링·OS 동작을 전부 재현한 것은 아님 |
| 기존 명세 대조 | 11번 공통 UI·화면 계약, 12·14번 진행 위치 계약, 15·17번 시즌 결정 | 과거 감사 내용을 현재 결함으로 그대로 인용하지 않음 |
| 로컬 웹 화면 확인 | 기존 `localhost:8081` 사용. 온보딩 390×844, 로그인 390×844·320×568·844×390 | 인증 세션이 없어 로그인 이후 화면은 직접 검증하지 못함 |
| DOM 실측 | 390×844 로그인 링크 높이: 계정 만들기 42px, 비밀번호 설정/재설정 34px, 첫 사용자 안내 17px | 네이티브 pt/dp 실측값은 아님 |
| 순수 함수 재현 | 실제 `onChangeText` 변환식과 시간 분류 함수를 연결하여 잘못된 입력의 의미 변경 확인 | DB 저장 요청은 실행하지 않음 |

844×390 로그인에서는 상단 로고와 하단 안내가 잘리고 스크롤 시도 후에도 하단에 접근할 수 없었다. 이 결과는 **모바일 웹 가로 화면**에 대한 것이다. `app.config.ts`는 네이티브를 `portrait`로 설정하므로 네이티브 가로 모드 결함으로 주장하지 않는다. 네이티브의 작은 세로 화면·키보드 표시·글자 확대는 별도 검증해야 한다.

코드를 수정하거나 로그인, 데이터 등록·수정·삭제, 배포를 실행하지 않았다. 전체 테스트·타입 검사·린트 통과 여부는 이번 분석의 검증 범위가 아니다.

## 3. 유지할 장점

1. `app/_layout.tsx`의 `GlobalBottomNav`는 이미 `(tabs)`에서만 표시한다. 11번 문서의 과거 지적과 달리, 상세·작성 화면에서 탭이 표시되는 문제는 현재 코드에서 수정되어 있다.
2. `src/utils/pinResponsive.ts`는 768 미만에서 핀 상세 패널을 숨긴다. 이 기준과 단일 열 핀 목록을 유지한다.
3. 라이브러리는 일반 스마트폰 폭에서 2열 갤러리와 목록 보기를 제공하고 FlashList를 사용한다. 모바일 필터 시트에는 하단 inset, 적용 버튼, 닫기 처리가 있다.
4. `EpisodeSelector`의 체크 터치 영역은 시각적 체크박스 28보다 큰 44이다. `EpisodeProgressCard`의 40 크기 증감 버튼에도 `hitSlop={4}`가 있으므로 단순히 “40이라 기준 미달”로 판정하면 안 된다.
5. 진행 위치 입력에는 직접 숫자 입력, 다음 회차 안내, 저장 버튼, 미설정/0 구분이 있다. 해당 의미와 기존 회귀 테스트를 유지한다.
6. 핀 생성과 명시적인 편집 모드가 구분되고, 저장 중 중복 제출 방지와 시간 분류·검증 함수가 존재한다. 입력 UI와의 연결을 보완하는 방식이 적절하다.

### M-01: 메뉴 개수만 줄여서는 해결되지 않는다

현재 필요한 최소 너비는 464이다. 390 화면과는 74 차이가 난다. 메뉴를 5개로만 바꾸어도 `5×72+32=392`이므로 작은 기기에서 계속 넘친다. 항목을 사용 가능한 너비 안에 배치하고 긴 라벨·글자 확대까지 검증해야 한다.

### M-04: 순수 함수만 검사하면 놓치는 입력 문제

실제 입력 변환식과 분류 함수를 연결한 결과다. 저장 버튼을 누르거나 서버에 요청한 실험은 아니다.

| 입력 원문 | 원문 분류 | 현재 입력 UI 변환 후 | 저장 단계가 받는 분류 |
|---|---|---|---|
| `12:3x` | invalid_nonempty | `123` | valid, 83초 (`01:23`) |
| `::` | invalid_nonempty | 빈 문자열 | empty, 메모가 있으면 시간 없는 핀 조건 충족 |
| `12:60` | invalid_nonempty | `1260` | invalid_nonempty |
| `1432` | valid | `1432` | valid, 872초 (`14:32`) |
| `90` | valid | `90` | valid, 90초 (`01:30`) |

숫자 키보드 사용은 유지할 수 있지만 붙여넣기·외부 키보드에서 들어오는 원문의 의미를 지우면 안 된다. “숫자만 입력”과 “잘못된 입력을 조용히 수정”은 별개다.

## 5. 목표 화면과 작업 흐름

| 화면 | 스마트폰 목표 구성 | 완료 기준 |
|---|---|---|
| 홈 | 최근 기록/보는 중 요약 → 최근 핀 → 검색 진입 | 다음 기록 행동이 첫 화면에서 보이고 보는 중 카드가 3열로 압축되지 않음 |
| 라이브러리 | 제목 검색 → 상태 → 목록/2열 갤러리 → 상세 필터 시트 | 직접 진행 위치 수정과 이어보기 경로 유지. 제목·시즌·상태를 구분 가능 |
| 검색 | 검색창 → 필터 개수 → 결과 | 필터 선택 중 결과가 반복 재조회되지 않고 적용 시 한 번 반영 |
| 콘텐츠 상세 | 뒤로 → 작은 포스터·제목 → 내 기록 요약·핵심 CTA → 진행 위치 → 부가 정보 | 시리즈는 에피소드 선택, 영화는 바로 핀 작성. 줄거리·인물보다 기록 버튼 우선 |
| 에피소드 | 뒤로·작품/시즌 → 진행 요약 → 회차 목록 | 완료 체크, 핀 목록 열기, 핀 추가가 구분되고 각 조작 영역 확보 |
| 핀 작성 | 작품/회차 → 시간·메모 → 선택 속성 → 저장 영역 | 키보드 표시 중 입력·첫 오류·저장에 접근. 올바른 작품/회차에만 저장 |
| 핀 상세 | 작품/회차·시간 → 스포일러 gate/메모 → 태그·감정 → 편집 | 긴 메모를 끝까지 읽고 돌아갈 수 있음 |
| 인증 | 명확한 필드 라벨 → 입력 → 오류 → 제출·보조 링크 | 작은 유효 높이에서도 스크롤 가능. 글자 확대 시 조작이 사라지지 않음 |

추가 제안: 태그·감정은 접을 수 있지만 스포일러 설정은 항상 쉽게 찾을 수 있게 둔다. 신규 애니메이션·햅틱·제스처 전용 액션보다 위 동선을 먼저 개선한다.

## 6. 기존 결정과 범위 경계

- 11번 문서의 MVP에서 인물·추천·공유·리뷰·가져오기는 제외되어 있으나 현재 UI에는 존재한다. MVP 구성에서는 노출과 불필요한 호출을 차단하되 파일 삭제, 기록 삭제, 공유 링크 회수, 서버 배포 정책 변경은 이 사용성 개선에 포함하지 않는다.
- 확장 기능을 출시 범위에 유지하기로 별도 합의된 경우에는 그 최신 문서를 근거로 노출 정책을 조정한다. 명세와 현재 코드의 차이를 임의로 새로운 제품 결정으로 확정하지 않는다.
- `status`/`status_flags`의 데이터 정합성 결정은 11번 문서 OPEN-010과 관련된다. 이번 UI 개선을 이유로 단일 상태 마이그레이션이나 데이터 재해석을 하지 않는다.
- 진행 위치의 `NULL`/0 구분, 수동값 우선, 시즌 상대 회차 저장, 동기화, 상태 전환 제안은 12·14번 규칙을 따른다. Enter만으로 진행 위치를 저장하지 않는다.
- 시즌 검색/등록은 15·17번 규칙을 유지한다. 같은 콘텐츠의 시즌 항목을 UI에서 합치거나 `library_item_id` 대신 content ID만으로 대상을 선택하지 않는다.
- 핀은 정수 초 저장, 영화 `episode_id = NULL`, 시리즈의 정확한 episode 선택, 같은 시간의 복수 핀 허용을 유지한다.
- Expo SDK 54·React Native 0.81·기존 Query/상태 구조를 기준으로 작은 단위로 수정한다. 라이브러리 업그레이드나 전역 상태 관리 교체는 범위 밖이다.

## 7. 검증 환경

- 모바일 웹: 320×568, 360×800, 390×844, 430×932, 844×390.
- 반응형 경계: 767, 768, 1199, 1200 폭. 핀 패널은 유효 본문 폭이 부족하면 단일 열로 복귀한다.
- 네이티브: iOS 노치/홈 인디케이터 기기, Android 제스처 및 3버튼 내비게이션. 세로 방향과 키보드 표시를 검증한다.
- 기본 글자와 크게 확대한 글자(가능한 환경에서 200%), VoiceOver/TalkBack, 긴 한국어 제목, 포스터 없음, 500자 메모, 여러 시즌과 200화 목록.
- 브라우저 뷰포트 검사는 소프트 키보드·Safe Area·네이티브 스크린 리더 검증을 대신하지 않는다.

## 9. 참고 기준

- 기본 터치 영역 44×44는 [프로젝트 화면 명세 §10.3](./11_screen_implementation_spec.md)의 요구다. Android 주요 조작을 48dp 이상으로 잡는 제안은 [Android Developers 접근성 지침](https://developer.android.com/guide/topics/ui/accessibility/views/apps-views?hl=en)에 근거한다. pt/dp와 웹 CSS px를 물리 픽셀로 혼동하지 않는다.
- 키보드 회피는 플랫폼별 behavior와 헤더 offset을 검증해야 한다. [React Native 0.81 KeyboardAvoidingView](https://reactnative.dev/docs/0.81/keyboardavoidingview)를 기준으로 하되, 컴포넌트 추가만으로 실기기 검증을 대체하지 않는다.
- 카드 순서·정보 축약·필터 시트 통일은 현재 코드와 기록 중심 제품 목표를 바탕으로 한 설계 제안이다. 사용자 실험으로 효과가 입증되었다고 주장하지 않는다.
