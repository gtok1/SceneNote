# 81. 라이브러리 한국 드라마 필터의 예능·일본 드라마 혼입 정정

작성일: 2026-11-19

선행 문서: [00 UI 스타일 규칙](00_ui_style_rules.md), [37 프로필 대시보드](37_profile_dashboard_redesign_spec.md)(D-4 공통 분류), [35 검색 분류 정정](35_search_completeness_and_deploy_drift_spec.md), [69 공개 메타데이터 영속 저장](69_persistent_public_metadata_cache_fixes_spec.md)

## 1. 문제 정의

사용자 요청: “라이브러리에 한국 드라마 장르를 선택하고 보는데 예능과 일본드라마가 섞여있어 필더 체크해서 수정해줘.” 이 화면에서 ‘한국 드라마’는 장르 칩이 아니라 **작품 유형**이다.

| ID | 증상 |
|----|------|
| F-1 | 예능·토크·뉴스·다큐멘터리가 ‘한국 드라마’ 또는 다른 드라마 유형에 섞인다 |
| F-2 | 일본어 원제인 작품이 저장 유형 `kdrama`를 따라 ‘한국 드라마’에 표시된다. 사용자 후속 캡처의 ‘가스인간’이 한 사례다 |

같은 작업의 읽기 전용 DB 표본에서 확인한 `kdrama` + 일본어 원제 3건:

| 작품 | TMDB TV ID | 저장된 원제 |
|------|------------|-------------|
| K-연하남 주의보 | 315631 | 韓ドラみたいな彼と私 |
| 로맨틱 어나니머스 | 249054 | 匿名の恋人たち |
| 가스인간 | 253960 | ガス人間 |

표본은 현재 저장값의 근거이며 국가·제작 국적의 확정 자료는 아니다.

## 2. 근본 원인

수정 전 `src/utils/libraryFilters.ts:110-119`의 `libraryContentCategory`는 `other`에 표시 장르 ‘드라마’가 있으면 `foreign_drama`, 그 외에는 저장 `content_type`을 그대로 반환한다. 비드라마 장르나 원제를 확인하지 않는다. `filterLibraryItems`의 유형 비교, `ContentCard`·`ContentGalleryCard`의 유형 라벨, `profileStats.ts`의 `createContentTypeStats`가 모두 이 함수를 사용한다.

서버의 TMDB 검색·상세 분류는 애니 구분 뒤 `origin_country`에 KR이 있으면 `kdrama`, JP이면 `jdrama`다. 국가만 보고 예능도 드라마 유형으로 저장할 수 있다. 현재 `LibraryListItem`에는 국가·원어 메타데이터가 없고, 등록된 과거 유형을 필터가 재검사하지 않는다. 이번 수정은 추가 조회 없이 이미 가진 장르·원제를 사용한다.

## 3. 재현 시나리오

1. 로그인한 라이브러리에서 작품 유형 ‘한국 드라마’를 선택한다.
2. 장르에 Reality 등 명시 비드라마 장르가 있거나 1장 표본처럼 원제가 일본어인 저장 항목을 확인한다.
3. 수정 후 예능 등은 ‘기타’, 표본 3건은 ‘일본 드라마’에서 찾을 수 있어야 한다. ‘전체’에서는 계속 보인다.

## 4. 설계 결정

### D-1. 기존 공통 함수 한 곳에서 앱 표시만 보정한다 (최우선)

`libraryContentCategory`의 반환 분류를 고친다. 입력 항목과 DB의 `content_type`은 변경하지 않는다. 필터·카드 유형 라벨·프로필 통계가 같은 반환값을 사용한다. docs/37 D-4의 ‘그 외는 content_type’ 및 `other + 드라마` 규칙은 **D-2·D-3에 해당하는 경우만** 이 사용자 요청으로 대체하고 나머지는 보존한다.

### D-2. 영화·애니를 보존하고 명시 비드라마 장르를 먼저 처리한다

- `movie`·`anime`는 원제·다른 장르와 무관하게 그대로 반환한다.
- 나머지 유형에서 정규화한 장르에 `Reality`/`리얼리티`, `Talk`/`토크`, `News`/`뉴스`, `Documentary`/`다큐멘터리`, `예능` 중 하나라도 있으면 `other`다. 기존 `createDisplayGenreNames`의 영문 대소문자·앞뒤 공백 정규화를 재사용한다.
- ‘Drama + Documentary’처럼 함께 있으면 비드라마 장르가 우선이다. 코미디·범죄·SF 등만 있다는 이유로 드라마에서 제외하지 않는다.

### D-3. 좁은 일본어 원제 신호만 일본 드라마 표시로 보정한다

기존 `content_type === "kdrama"`, `source_api === "tmdb"`, `title_original`에 **히라가나 또는 가타카나 글자가 있고 한글이 없을 때만** `jdrama`로 반환한다. 가운데점·장음부호 같은 문장 부호만으로 판정하지 않는다.

번역된 `title_primary`, 한자만 있는 원제, 원제 누락·빈 값, 한글이 섞인 원제, 수동 등록 작품은 이 보정의 근거가 아니다. 기존 `jdrama`를 역으로 `kdrama`로 바꾸지 않는다. D-2가 D-3보다 먼저다.

### D-4. 작품 보존과 기존 필터 계약을 유지한다

분류 보정은 유형 필터의 위치를 옮기는 것이며 작품을 숨기거나 삭제하지 않는다. ‘전체’의 항목·기존 정렬·상태·장르·평점·연도·공백 무시 검색은 유지한다. `other` + ‘드라마’의 기존 해외 드라마 판정은 D-2 대상이 아닐 때만 유지한다.

### D-5. 요청·DB·서버를 변경하지 않는다

라이브러리 카드마다 국가나 외부 상세를 추가 조회하지 않는다. DB 쓰기·마이그레이션·백필·Edge Function 수정·배포·캐시 버전 변경이 없다. 국가 provenance의 저장과 기존 데이터의 확정 보정은 별도 작업이다.

> D-N은 임의로 바꾸지 않는다. 변경이 필요하면 구현하지 말고 이유를 보고한다.

## 5. 기각한 대안

| 대안 | 기각 이유 |
|------|-----------|
| 한국 드라마 유형에 ‘드라마’ 장르를 필수로 요구 | 범죄·SF 등만 분류된 정상 극작품을 누락시킨다 |
| 한국어 표시 제목이나 한자만으로 국가 추정 | 번역 제목과 한중일 공통 문자를 국적 근거로 쓸 수 없다 |
| 필터에서만 제외하거나 작품 삭제 | ‘전체’·다른 유형·프로필과 불일치하고 개인 기록을 훼손한다 |
| 목록의 모든 작품을 외부 API로 재분류 | 추가 호출·오류·지연이 생기며 이번 앱 보정 범위를 넘는다 |

## 6. 계약 (타입·판정 순서)

`libraryContentCategory`는 기존 호출부의 `content_type`·`genres`만 있는 입력도 계속 허용한다. `source_api`·`title_original`은 선택적 근거로 읽는다. 반환 타입 `LibraryContentCategory`와 `filterLibraryItems`의 공개 시그니처는 유지한다.

판정 순서: **movie/anime 보존 → 명시 비드라마 장르 other → D-3 일본어 원제 보정 → 기존 other+드라마 foreign_drama → 저장 유형**. 소스·원제를 전달하지 않는 호출은 D-3만 실행하지 않으며 실패하지 않는다.

## 13. 확실하지 않음 — 별도 검증 필요

가나 신호는 **원제 언어에 따른 라이브러리 표시 휴리스틱**이다. 국가·제작 국적의 확정 판정이 아니며 한일 합작도 이 규칙에 따라 일본 드라마로 표시될 수 있다. 현재 라이브러리는 국가 provenance를 갖고 있지 않으므로 모든 오분류가 해결됐다고 단정하지 않는다. 새로운 반례는 별도 국가 메타데이터 설계와 함께 검토한다.

### 바꾸면 안 되는 설계 결정

D-1~D-5 전부 준수. 분류를 화면에 복제하지 않고 기존 공통 함수를 확장한다. 기존 함수·반환 타입을 삭제하지 않으며 기존 최소 입력도 유지한다. API 요청·DB 쓰기·Edge 배포가 없어야 한다.

### STEP 1 — 실패 재현

`pwd`·Git 루트·`git status --short`·브랜치/SHA를 기록하고 10장 T-1~T-5를 기존 테스트에 추가한다. scenenote-verify로 두 관련 파일을 실행해 결함 사례가 구현 전 실패하는지 확인한다. 실패하지 않으면 원인을 재검토하고 보고한다. 기존 assertion을 완화하지 않는다.

### STEP 2 — 공통 분류 정정

수정 전 `if (item.content_type !== "other") return item.content_type`가 예능·일본어 원제 항목을 통과시키는 지점이다. 이를 6장의 판정 순서로 교체한다. 원본 항목은 수정하지 않는다. 국가 확정이 아닌 표시 휴리스틱임을 코드 주석에 남긴다. 관련 테스트를 다시 실행한다.

### STEP 3 — 공통 사용처·화면 검증

`libraryContentCategory` 사용처를 검색해 필터·카드·통계가 같은 함수를 쓰는지 확인한다. 10장 수동 표를 웹 8081과 가능한 네이티브 환경에서 확인하고 미실행 행의 이유를 남긴다. 실제 사용자 기록을 테스트 목적으로 임의 삭제·수정하지 않는다.

두 번째 명령은 `npm test`·`npm run typecheck`·`npm run lint` 전체 검증을 수행한다. 실패는 로그와 기준선으로 구분하고 임의로 누락하지 않는다. UI-13.2 토큰·`Alert` 검사는 이번 변경분 0줄이어야 하며 이를 위해 무관한 기존 화면 코드를 정리하지 않는다.

- [ ] 기존 테스트 감소·assertion 완화 없음, 타입·린트·diff 결과 보고.

- [ ] UI-13.2 토큰·`Alert` 검사 0줄, 웹·앱 수동 확인 표 보고.
