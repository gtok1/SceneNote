# Codex 작업 요청: 보는 중 카드에 "다음 볼 화" 표시 및 이어보기 진입

## 배경

- 에피소드별 시청 체크 기능은 이미 구현돼 있다
  (`useEpisodeProgress`, `useToggleEpisodeProgress` — `src/hooks/useLibrary.ts`,
  `user_episode_progress` 테이블).
- 그러나 이 데이터가 카드 UI에 전혀 활용되지 않는다. 라이브러리/홈 카드에는
  회차 시청 진행과 무관한 "시청 N회"(작품 단위 `watch_count`)만 표시된다.
- "어디까지 봤더라?"에 답하고 다음 화로 바로 진입시키는 것이
  감상 기록 → 이어보기 → 핀 기록 루프의 핵심 연결 고리다.

## 목표

1. 보는 중(`watching`) 상태의 작품 카드에 "다음: N화" 형태로 다음 볼 화를 표시한다.
2. 해당 표시를 탭하면 그 작품의 에피소드 화면(`/content/[id]/episodes`)으로 이동한다.
3. 시청한 에피소드 수 기반 진행률(예: "7/13화")을 함께 표시한다.

## 현재 코드/데이터 상황 (반드시 참고)

- `LibraryListItem`(`src/types/library.ts`)에 `episode_count`(작품 총 화수, nullable)가 이미 있다.
- `EpisodeProgress` 타입: `{ episode_id, content_id, watched_at, ... }` —
  **episode_number가 없다.** 화수를 알려면 `episodes` 테이블과 조인이 필요하다.
- `src/services/library.ts`의 `getLibraryItems`가 라이브러리 목록 쿼리의 진입점이다.
  여기서 어떤 뷰/쿼리를 쓰는지 먼저 확인할 것 (pin_count를 이미 집계하고 있다면
  같은 방식으로 진행 집계를 붙이는 것이 자연스럽다).
- 카드 컴포넌트: `src/components/content/ContentGalleryCard.tsx`(갤러리),
  `src/components/content/ContentCard.tsx`(리스트). 두 곳 모두 반영한다.

## 구현 지시

### 1. 데이터: 라이브러리 목록에 진행 정보 추가

- `LibraryListItem`에 다음 필드를 추가한다:
  - `watched_episode_count: number` — 해당 작품에서 사용자가 체크한 에피소드 수
  - `next_episode_number: number | null` — 다음 볼 화 (아래 규칙)
- 집계 방법은 `getLibraryItems`의 기존 쿼리 구조에 맞춰 결정하되, 원칙:
  - **N+1 쿼리 금지.** 작품마다 개별 조회하지 말고 목록 쿼리 1~2회로 집계한다.
  - 클라이언트에서 `user_episode_progress`를 `content_id in (...)`으로 한 번에
    가져와 매핑하는 방식도 허용 (RLS로 본인 데이터만 조회됨).
  - DB 뷰/함수를 추가하는 방식을 택할 경우 마이그레이션 파일은
    `supabase/migrations/`에 기존 번호 체계(예: `0013_...sql`)를 따라 추가한다.
- 다음 볼 화 계산 규칙:
  - 시청 체크된 에피소드들의 `episode_number` 최댓값 + 1.
  - 단, 그 값이 `episode_count`를 초과하면 `null` (완주 상태로 간주).
  - 시청 체크가 하나도 없으면 `1`.
  - `episode_number`는 `episodes` 테이블에서 가져온다.

### 2. UI: 카드 표시

- 대상: 보는 중(`watching`) 상태 카드만. 다른 상태는 기존 표시 유지.
- 표시 형식:
  - 진행 있음: `다음: 8화 · 7/13화 시청`
  - 진행 없음: `1화부터 시작`
  - 총 화수 미상(`episode_count` null): `다음: 8화` (분모 생략)
  - 완주(다음 화 null): `모든 화 시청` 또는 표시 생략 중 기존 카드 밀도에 맞는 쪽 선택
- 탭 동작: 진행 표시 영역 탭 → `/content/[id]/episodes`로 이동.
  카드 본체 탭(콘텐츠 상세 이동)과 이벤트가 겹치지 않게 분리한다.
- 홈(`app/(tabs)/index.tsx`)의 보는 중 섹션과 라이브러리 탭 모두에 적용된다
  (같은 카드 컴포넌트를 쓰므로 카드 레벨에서 해결).

## 주의사항 (확실하지 않은 부분 — 가정 금지)

- **에피소드 캐시 부재 가능성**: 이 앱은 bulk 캐싱을 금지하므로, 사용자가
  에피소드 화면을 연 적 없는 작품은 `episodes` 테이블에 row가 없을 수 있다.
  이 경우 `episode_number` 조인이 불가능하다.
  - 처리: 시청 체크 자체가 에피소드 화면에서만 가능하므로, 체크가 있는 작품은
    episodes 캐시가 존재한다고 볼 수 있다. 체크가 0개인 작품은 조인 없이
    "1화부터 시작"으로 처리하면 된다. 이 가정이 실제 데이터와 다르면
    (체크는 있는데 episodes row가 없는 경우) 해당 작품은 진행 표시를 생략하고,
    결과 보고에 그 사실을 명시한다.
- 시즌이 여러 개인 작품의 화수 계산 방식(시즌 내 번호 vs 통산 번호)은
  `episodes.episode_number` 저장 방식을 확인한 뒤 그에 맞춘다. 확인 결과를
  보고에 포함할 것.

## 범위 제외

- 에피소드 화면 자체의 UI 변경
- watch_count(회차 반복 시청) 로직 변경
- 자동 시청 체크(핀 생성 시 자동 체크 등)

## 수용 기준 (Acceptance Criteria)

1. 에피소드를 7개 체크한 13화짜리 보는 중 작품 카드에 "다음: 8화 · 7/13화 시청"이 표시된다.
2. 체크가 없는 보는 중 작품에는 "1화부터 시작"이 표시된다.
3. 진행 표시 탭 → 해당 작품 에피소드 화면으로 이동한다.
4. 라이브러리 목록 로딩 시 작품 수에 비례하는 추가 쿼리(N+1)가 발생하지 않는다.
5. 보는 중이 아닌 카드(보고 싶음/완료 등)는 기존과 동일하다.
6. `npx tsc --noEmit`, `npx eslint .` 통과.

## 검증 방법

- 에피소드 화면에서 몇 개 체크 → 홈/라이브러리로 돌아와 표시 갱신 확인
  (TanStack Query 캐시 무효화가 `useToggleEpisodeProgress`에 이미 있는지 확인하고,
  없으면 라이브러리 목록 쿼리 키 무효화를 추가).
- 체크 0개 작품, episode_count null 작품, 완주 작품 3가지 엣지 케이스 확인.
