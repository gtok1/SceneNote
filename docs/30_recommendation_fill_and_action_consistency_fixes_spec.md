# 30. 추천 12개 보충과 카드 행동 일관성 재수정 명세

작성일: 2026-09-24  
대상 브랜치 기준: `main` (`ca4e285`, 미커밋 수정 포함)  
선행 문서: `docs/11_screen_implementation_spec.md`, `docs/22_search_recommendations_restore_spec.md`, `docs/27_excluded_relationship_themes_spec.md`, `docs/28_recommendation_scroll_pagination_fixes_spec.md`

## 1. 문제와 재현

| 결함 | 사용자 화면 | 코드상 원인·한계 |
|---|---|---|
| F-1 | “새 추천 12개” 이후 2~4개만 보이고 탐색 시간 초과가 뜸 | Edge는 호출마다 한 번의 공급자 범위에서 최대 12개를 반환한다. 계정별 하드 제외·등록 작품·중복 제거 뒤 실제 표시 수는 더 적다. 이전 hook의 별칭 기반 표시 수와 `app/search.tsx`의 등록 판정이 달라 자동 보충이 일찍 멈출 수 있었다. 이전 전체 탐색 예산보다 후속 요청의 12초 제한이 길어 남은 예산이 짧은 호출에서 인위적 타임아웃도 발생했다. **첨부 화면만으로 원격 서버 지연과 이 인위적 타임아웃 중 어느 것이 발생했는지는 단정하지 않는다.** |
| F-2 | 같은 행에서도 “이런 요소 줄이기” 아이콘이 있는 카드와 없는 카드가 섞임 | `docs/28` D-5가 행동 불가능 카드에 빈 슬롯을 요구했기 때문이다. 위치는 맞아도 눈에 보이는 아이콘 수가 달랐다. |

재현: 관계 테마·장르 제외를 설정한 계정에서 빈 검색어의 추천을 새로 요청하고 12개 미만일 때 카드 끝까지 스크롤한다. 이어 같은 행에 `onReduceTheme` 유무가 다른 카드의 하단 행동을 비교한다.

인증된 화면의 추가 관측에서는 여러 번 스크롤한 뒤 원시 후보 132개 중 12개가 표시됐고, 118개는 TMDB 관계 테마 판정에 필요한 키워드가 없어 제외됐다. 이는 하드 제외가 작동한다는 근거이면서 후보 보강에 쓰는 제한된 조회를 이미 볼 수 없는 작품에 낭비하면 안 된다는 근거다. 해당 관측만으로 배포 서버가 최신 로컬 코드를 실행 중인지는 확인되지 않는다.

## 2. 설계 결정

### D-1. 12개는 실제 표시 가능한 고유 작품의 목표 상한이다

`docs/22` D-2의 배치 목표 12개를 유지하되, 공급자·메타데이터·필터 조건에서 12개가 없으면 실제 개수만 보여준다. 가짜 카드, 같은 작품 중복, `docs/27`의 계정별 관계 테마·장르 하드 제외 완화로 숫자를 채우지 않는다. 제외 설정이 켜진 계정에서 테마를 판정할 수 없는 TMDB 후보를 안전하지 않게 통과시키지 않는다.

### D-2. 화면과 보충 로직은 같은 ‘표시 가능’ 판정을 쓴다

`app/search.tsx`와 `src/hooks/usePersonalizedRecommendations.ts`가 등록 작품(원본 ID 또는 유형·정규화 제목, 연도가 **둘 다 알려졌을 때만** 연도 불일치) 및 현재 계정의 테마·장르 제외를 같은 순수 함수로 판정한다. UI에서 숨길 후보를 hook이 12개로 세어 자동 보충을 멈추지 않는다. 보충 성공 여부도 원시 응답 수가 아니라 새로 보이는 고유 작품 수로 판정한다.

### D-3. 짧은 피드는 유한하게 보충하고 요청마다 시간을 온전히 준다

`docs/28` D-3의 스크롤 재개·무한 반복 방지를 유지한다. 한 자동 보충 주기는 **최대 6회·45초**, 새로 보이는 카드가 **3회 연속 0개**면 중단한다. 후속 요청을 시작하려면 12초의 호출 예산이 남아 있어야 한다. 남은 주기 예산이 부족한 것은 서버 타임아웃으로 표시하지 않는다. 실제 네트워크 오류·타임아웃에서는 기존 카드를 유지하고 재시도를 제공한다. 유효 커서와 새 사용자 스크롤이 있으면 다음 제한 주기로 탐색할 수 있다.

### D-4. 세 번째 아이콘은 모든 카드에 보이되 행동이 없으면 비활성이다

최신 사용자 재확인에 따라 **이 결정만 `docs/28` D-5의 ‘빈 슬롯’ 요구를 대체한다.** 갤러리·목록 카드 모두 세 번째 아이콘을 같은 순서·44×44pt 영역에 표시한다. `onReduceTheme`가 없으면 흐리게 표시하고 눌러도 실행하지 않으며, 접근성 상태와 힌트로 “조절할 수 있는 테마 정보가 없음”을 알린다. 관심 없음·비슷한 작품·빠른 보기·추가 버튼의 위치와 작동도 일관되게 유지한다.

### D-5. 키워드 조회 예산은 실제 후보에 우선 쓴다

현재 계정이 관계 테마 제외를 켰을 때만 TMDB 키워드를 최대 8개 후보에 제한적으로 조회한다. 조회 전에 계정의 제외 장르를 걸러내고, 라이브러리·최근 본 작품·요청의 `exclude_ids`·관심 없음/제외 피드백과 겹치는 identity에는 조회 예산을 쓰지 않는다. 남은 후보에만 키워드를 보강해 관계 테마를 판정한다. 조회 상한 초과·키워드 없음·조회 실패 후보는 `docs/27` D-7대로 **판정 불가로 제외**한다. 관계 테마 제외를 설정하지 않은 계정에는 이 추가 조회를 하지 않는다. 이는 로컬 Edge Function 코드 개선이며 배포 전 운영 피드의 12개 표시를 보장하지 않는다.

## 3. 기각한 대안·계약

| 대안 | 기각 이유 |
|---|---|
| 하드 제외를 끄거나 후보를 복제해 항상 12개 표시 | 사용자별 제외 의도와 신뢰를 깨뜨린다 |
| 보이는 수와 상관없이 원시 12개가 오면 보충 종료 | 2~4개만 남는 현재 결함을 재현한다 |
| 시간·진전 제한 없이 빈 배치를 재호출 | 무한 로딩과 과도한 공급자 호출이 재발한다 |
| 비활성 아이콘을 숨기고 자리만 확보 | 같은 행의 아이콘 노출이 달라진다는 최신 불만을 해결하지 못한다 |

판정 순서: **계정·화면 활성·제외 설정 준비** → 현재 응답에서 **등록/제외/중복을 제거한 표시 수** → 12개 미만이면 커서·오류·진행 중 요청·보충 횟수/시간/무진전 제한 확인 → 남은 시간이 12초 이상일 때만 후속 호출 → 화면에 실제 추가된 고유 카드 수로 진전 기록. 서버 `has_more=false` 또는 커서 없음은 정상 종료이며 12개 미만이어도 그대로 끝난다. 한 공급자의 일부 실패와 전체 오류는 기존 오류 계약에 따라 구분한다.

## 4. 엣지 케이스·수용 테스트

**아래 모든 행을 자동 테스트 또는 실제 UI QA로 검증하고, 미검증 행을 통과로 보고하지 않는다.** 순수 판정 테스트는 `node:test`와 `node:assert/strict`를 쓰고 React Native·Supabase 런타임 모듈을 import하지 않는다.

| ID | 입력·상황 | 기대 결과 | 검증 |
|---|---|---|---|
| RFC-01 | 수동 등록 작품의 연도는 비어 있고 추천의 제목·유형은 같으며 연도만 있음 | 화면과 hook 모두 등록 작품으로 숨겨 표시 수가 같음 | `recommendationVisibility.test.ts` 자동 |
| RFC-02 | 원시 12개 중 계정별 관계 테마/장르 제외·등록 작품·중복이 섞임 | 화면에 남는 **고유** 카드 수로 보충 여부 결정; 하드 제외 작품 노출 없음 | 순수 함수 자동 + 필터 계정 UI |
| RFC-03 | 2~4개 표시, 유효 다음 커서, 공급자가 새 표시 가능 작품을 반환 | 기존 카드 유지·자동 이어붙임, 실제 가능한 범위에서 최대 12개로 진행; 가짜 카드 없음 | 보충 정책 자동 + 인증된 UI/네트워크 QA |
| RFC-04 | 후속 호출 제한 12초보다 주기 잔여 시간이 짧음 또는 새 카드 0개가 3회 연속 | 호출 시작/무한 로더 없음; 예산 소진을 서버 타임아웃으로 오인하지 않음; 새 사용자 스크롤로 제한 주기 재개 | `recommendationFeed.test.ts` 자동 + UI |
| RFC-05 | 실제 네트워크 타임아웃, 제공처 부족, `has_more=false` | 오류는 카드 유지·재시도, 정상 소진은 실제 카드 수와 종료 안내; 어떤 경우에도 12개 보장으로 표시하지 않음 | 오류 정책 자동 + UI/네트워크 QA |
| RFC-06 | `onReduceTheme` 유무가 다른 카드가 같은 행·목록에 있음; 320/360/390/430 폭과 큰 글자 | 세 번째 아이콘이 모두 보이고 불가능한 것만 비활성·접근성 설명; 다른 행동과 추가 버튼 정렬·44×44pt 유지 | 실제 웹/네이티브 UI·접근성 QA |
| RFC-07 | 관계 테마 제외 계정의 TMDB 후보 17개 중 앞의 8개가 라이브러리·최근 본 작품·관심 없음/제외에 해당하고 뒤의 9개가 새 후보임 | 앞의 8개와 제외 장르에 조회를 쓰지 않고 다음 새 후보 최대 8개만 키워드 조회; 초과·실패·키워드 없는 후보는 계속 제외. 관계 테마 제외가 없는 계정은 추가 조회 없음 | `recommendationProviders.test.ts` 자동 + 배포 후 인증된 네트워크 QA |

## 5. 변경 파일·범위

| 파일 | 책임 |
|---|---|

| `src/hooks/usePersonalizedRecommendations.ts`, `src/utils/recommendationFeed.ts` 및 `.test.ts` | 유한 보충·진전/시간 판정·오류 구분 |

| `supabase/functions/personalized-recommendations/index.ts`, `supabase/functions/_shared/recommendationProviders.ts` 및 `.test.ts` | 서버 후보 선별 뒤 제한된 TMDB 키워드 보강과 RFC-07 회귀 검증 |

범위 밖: Edge Function **배포**, DB/RLS, 추천 순위, 사용자별 제외 설정 저장 방식, 일반 검색의 페이지네이션. 서버 수정은 로컬 코드에만 있으므로 배포 전 운영 화면의 키워드 부족과 12개 미달이 계속될 수 있다. 배포 후 원격 공급자의 실제 지연·최종 카드 수는 인증된 동일 계정의 네트워크 로그와 UI에서 별도 확인한다. `npm test`, `npm run typecheck`, `npm run lint`를 실행한다.
