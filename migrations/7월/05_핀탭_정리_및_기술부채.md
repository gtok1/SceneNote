# Codex 작업 요청: 핀 탭 감정 통계 정합성 + 홈 Top10 빈 상태 + FlashList 전환

세 가지 독립적인 정리 작업 묶음. 순서 무관, 각각 별도 커밋으로 진행할 것.

---

## 작업 A. 핀 탭 감정 통계/필터 정합성

### 배경

- `EmotionType`(`src/types/pins.ts`)은 10종:
  `excited, moved, funny, sad, surprised, angry, scared, love, boring, none`
- 그런데 핀 탭(`app/(tabs)/pins.tsx`)의 상단 통계 카드는
  "전체 핀 / 감동 / 명장면 / 명대사" 3종만 집계한다. 예: 슬픔(sad) 핀은
  전체 핀 수에는 잡히지만 어느 감정 카드에도 나타나지 않아 숫자가 안 맞아 보인다.
- 필터 칩의 라벨-값 매핑도 어긋나 있다
  (`pins.tsx`의 `emotionFilterOptions`: `excited`→"명장면", `love`→"명대사").
  enum 의미(excited=신남, love=사랑)와 라벨(명장면, 명대사)이 다르다.

### 목표

감정 라벨을 한 곳에서 관리하고, 통계 카드가 실제 데이터 분포와 일치하게 한다.

### 구현 지시

1. `src/constants/emotions.ts`의 `EMOTION_LABELS`를 단일 진실 공급원으로 삼는다.
   `pins.tsx`의 로컬 `emotionFilterOptions` 라벨이 `EMOTION_LABELS`와 다르면
   `EMOTION_LABELS` 쪽 정의를 확인하고 **라벨 정의를 한 곳으로 통일**한다.
   - "명장면", "명대사"라는 개념이 제품에 필요하다면 감정(emotion)이 아니라
     별도 분류이므로, 이번 작업에서는 emotion 라벨을 enum 의미에 맞게
     (excited=신남/흥분, love=사랑/설렘 등) 정리하는 것까지만 한다.
     명장면/명대사를 태그 프리셋으로 옮기는 것은 후속 과제로 보고서에 남긴다.
2. 통계 카드를 고정 3종이 아니라 **실제 존재하는 감정별 카운트**로 바꾼다:
   - "전체 핀" 카드는 유지.
   - 그 뒤로 현재 사용자의 핀에 존재하는 감정만, 카운트 내림차순으로 표시.
   - 감정 카드 탭 → 해당 감정 필터 토글 (기존 필터 상태와 연동).
   - 카드가 많아질 수 있으므로 가로 스크롤 허용.
3. 기존 DB 데이터는 건드리지 않는다 (라벨 표기만 정리, enum 값 변경 금지).

### 수용 기준

1. 모든 감정의 핀이 통계에 반영된다 (예: sad 핀 1개 → "슬픔 1" 카드 표시).
2. 감정 라벨이 필터 칩, 통계 카드, 핀 카드 뱃지에서 동일하다.
3. 감정 카드 탭으로 필터가 적용/해제된다.

## 작업 B. 홈 인기 추천 Top10 빈 상태 처리

### 배경

- 홈의 `PopularRecommendationSection`
  (`src/components/content/PopularRecommendationSection.tsx`)에서
  "드라마 Top 10" / "애니 Top 10" 두 그룹을 표시하는데, 한쪽 데이터가 비어 있으면
  화면 절반이 통째로 빈 공간으로 남는다 (현재 웹에서 애니 Top 10 영역이 빈 상태).

### 구현 지시

1. 먼저 컴포넌트 구조를 확인: 두 그룹이 탭 전환인지 병렬 배치인지 파악한다.
2. 데이터가 비어 있는 그룹 처리:
   - 로딩 중이면 스켈레톤(`LoadingSkeleton`) 표시.
   - 로드 완료 후 0건이면: 병렬 배치라면 해당 그룹을 숨기고 남은 그룹이
     전체 폭을 쓰게 한다. 탭 전환식이라면 빈 그룹 탭에
     `EmptyState`("추천 데이터를 불러오지 못했어요" + 재시도)를 표시한다.
3. `src/services/popularRecommendations.ts` /
   `supabase/functions/popular-recommendations`에서 애니 데이터가 왜 비는지
   원인을 확인하고, 데이터 자체의 버그라면 수정한다. 외부 API 원인으로
   확정이 어려우면 보고에 "확실하지 않음"으로 명시하고 UI 방어만 적용한다.

### 수용 기준

1. 어느 그룹이 비어도 화면에 큰 빈 공백이 남지 않는다.
2. 실패 시 재시도 수단이 있다.

## 작업 C. 핀 탭 목록 FlashList 전환

### 배경

- 핀 탭(`app/(tabs)/pins.tsx`)의 핀 목록이 `ScrollView` + `map` 렌더링이다.
- 핀은 이 앱의 핵심 자산으로 계속 쌓이므로 수백 개 규모에서 성능 저하가 예상된다.
- CLAUDE.md 원칙: 목록은 FlashList 우선.

### 구현 지시

1. `@shopify/flash-list`가 `package.json`에 있는지 확인, 없으면
   `npx expo install @shopify/flash-list`.
2. 핀 목록 부분만 `FlashList`로 교체한다. 필터/통계 헤더 영역은
   `ListHeaderComponent`로 넣거나 화면 구조상 자연스러운 방식을 택한다.
3. 우측 상세 패널(웹 와이드 레이아웃)과의 선택 동기화(`selectedPinId`) 동작을
   깨뜨리지 않는다.
4. 웹 플랫폼에서 FlashList 동작을 확인한다 (이 프로젝트는 웹도 사용 중).
   웹에서 문제가 있으면 `Platform.OS === "web"` 분기로 기존 방식을 유지하고
   보고에 명시한다.

### 수용 기준

1. 핀 100개 이상에서도 스크롤이 부드럽다 (개발 모드 기준 체감 확인).
2. 필터/정렬/검색/상세 패널 연동 등 기존 동작이 모두 유지된다.
