# SceneNote 스마트폰 UI 개선 실행 프롬프트

아래 내용을 개발 에이전트에 전달한다. 분석 근거와 수용 테스트는 [19_mobile_usability_spec.md](./19_mobile_usability_spec.md)에 있다.

---

SceneNote를 스마트폰에서 작품과 장면을 빠르고 정확하게 기록할 수 있도록 개선해라. 분석만 제시하지 말고, 아래 범위의 UI 구현과 적절한 검증까지 수행해라. 작업 시작 시 최신 코드에서 문제의 존재를 확인하고 이미 해결된 항목은 다시 변경하지 마라.

## 1. 먼저 읽을 문서

- `docs/11_screen_implementation_spec.md`
- `docs/12_episode_progress_spec.md`, `docs/13_codex_prompt_episode_progress.md`, `docs/14_codex_prompt_episode_progress_fixes.md`

## 2. 범위와 보존 조건

대상은 인증, 홈, 검색, 라이브러리, 작품 상세, 에피소드, 핀 생성·상세·편집과 그 공통 UI다. 기존 색상과 브랜드, Expo SDK 54·React Native 0.81·Expo Router·FlashList를 재사용해라.

- DB 스키마 변경, 서비스 계약 재설계, 전역 상태 관리 교체, 의존성 일괄 업그레이드는 하지 마라.
- 외부 API 키는 Edge Function에만 둔다. RLS·소유권 검증을 약화하거나 실제 키를 문서·로그에 출력하지 마라.
- 기존 변경을 보존하고 `docs/`, `.claude/`를 삭제하거나 덮어쓰지 마라. 새 QA 결과가 필요하면 별도 파일로 추가해라.
- 진행 위치의 NULL/0 구분, 수동값 우선, 시즌 상대 회차, 재동기화, 상태 전환 제안을 유지해라. 직접 진행 위치는 저장 버튼으로만 확정한다.
- 시즌별 라이브러리 항목은 `library_item_id`와 시즌을 유지해라. content ID만으로 첫 번째 항목을 고르거나 서로 다른 시즌을 합치지 마라.
- 영화 핀은 `episode_id = NULL`, 시리즈 핀은 해당 작품의 선택된 실제 episode ID를 사용한다. 같은 회차·같은 시간의 복수 핀을 허용한다.
- 정수 초 저장, 500자 메모, 태그 20자/10개, 생성·편집의 동일 시간 검증을 유지한다.
- 오프라인 쓰기 큐, 자동 공개 공유, 서버 배포, 데이터 삭제는 이번 범위에 넣지 마라.
- 네이티브의 현재 `portrait` 설정을 유지한다. 가로 레이아웃 검증은 모바일 웹에 적용한다.

## 3. P0 — 하단 메뉴, Safe Area, 돌아가기

대상: `app/_layout.tsx`, `app/(tabs)/_layout.tsx`, 관련 Stack 화면, 공통 레이아웃.

1. 현재 6개 메뉴의 `minWidth: 72`와 좌우 padding 때문에 필요한 폭이 464다. **메뉴 개수만 줄이지 말고** 사용 가능한 너비를 기준으로 균등 분배하도록 수정해라.
2. 별도의 최신 제품 결정이 없다면 11번 문서의 MVP 구성인 홈·검색·라이브러리·핀·프로필 5개를 사용한다. 인물 등 제외 기능의 코드를 삭제하지 않고 MVP 노출/호출을 가드한다. 현재 확장 기능 유지가 명시된 최신 문서가 있다면 그 근거를 보고하고 모바일 메뉴에 대한 해당 정책을 따른다.
3. `(tabs)`에서만 탭을 표시하는 현재 동작을 유지한다. 커스텀 탭 또는 Router 탭 중 하나가 공간과 내비게이션을 책임지게 하고 중복 렌더링을 피한다.
4. 하단 inset과 실제 탭 높이를 함께 계산한다. 각 화면의 고정 `paddingBottom: 92/104/112` 등을 실제 가려지는 영역에 맞게 바꾸어라. Stack에 없는 탭의 여백을 추가하지 마라.
5. 콘텐츠 상세와 에피소드 등 Stack에 명시적인 뒤로 버튼을 제공한다. 헤더가 이미 inset을 반영하는 경우 중복 padding을 피한다. 로딩·빈 상태·오류에서도 돌아갈 수 있어야 한다.
6. 이력이 없는 딥링크에서는 `/library` 또는 `/pins` 등 목적에 맞는 안전 경로로 복귀한다. 저장 성공 후에는 폼으로 다시 돌아가지 않고 원래 작품/회차의 핀 목록으로 복귀한다.
7. 글자 확대에서 메뉴 라벨이 잘리지 않게 줄바꿈·높이 조정을 허용한다. 작은 화면을 맞추려고 텍스트 스케일링을 끄거나 터치 영역을 축소하지 마라.

## 4. P0 — 키보드와 작은 유효 높이

대상: `app/(auth)/*.tsx`, `src/components/pins/PinComposer.tsx`, `app/pins/new.tsx`, `app/pins/[id].tsx`, `app/(tabs)/library.tsx` 진행 위치 모달, 상세 진행 입력.

1. 인증 폼을 스크롤 가능한 구조로 바꾸고 충분한 높이에서만 중앙 정렬한다. 화면/키보드가 줄어들면 모든 필드, 오류, 제출, 보조 링크를 스크롤로 볼 수 있게 해라.
2. iOS/Android에서 키보드에 맞는 회피 동작과 헤더 offset을 적용한다. OS resize와 별도 회피가 겹쳐 이중 여백이나 점프를 만들지 않는지 확인한다.
3. 핀 저장 영역은 폼 스크롤과 분리해 접근 가능하게 두고, 실제 높이만큼 본문 여백을 확보한다. 키보드가 보일 때에도 마지막 필드와 저장 버튼이 서로 가리지 않아야 한다.
4. 진행 위치 모달에도 키보드 회피·하단 inset을 적용하고 긴 내용은 내부 스크롤로 접근시킨다. 저장 중 닫기와 중복 제출은 기존 정책대로 차단한다.
5. 인증 필드에는 보이는 라벨과 접근성 이름을 제공한다. React Hook Form의 ref를 입력에 연결하여 첫 오류 포커스가 작동하게 하고, 이메일/비밀번호의 자동 완성과 다음 입력 이동을 적절히 제공한다.

## 5. P0 — 시간 입력이 원문 의미를 바꾸는 문제

대상: `src/components/pins/TimecodeInput.tsx`, `src/components/pins/PinComposer.tsx`, `src/utils/timecode.ts`, 관련 순수 함수 테스트.

현재 `text.replace(/\D/g, "")` 때문에 `12:3x`는 `123`으로 바뀌어 83초가 되고, `::`는 빈 값이 된다. 원문을 보존해 먼저 분류하고 **유효한 입력만 정규화**해라. blur뿐 아니라 저장 직전에도 같은 입력 계약을 적용해라.

- `14:32`, `1432` → 872초, `90` → 90초, `1:02:30` → 3750초, `0` → 0초.
- `12:60`, `1:60:00`, `12:3x`, `::` 등은 오류다. 문자 삭제로 다른 유효값/빈 값으로 바꾸지 않는다.
- 빈 시간+유효 메모는 허용하고, 둘 다 공백이면 차단한다.
- 숫자 키보드와 붙여넣기를 지원하되 입력할 때마다 마스킹하여 커서를 끝으로 보내지 않는다. 유효한 값의 blur/저장 정규화와 입력 중 상태를 구분한다.
- “1432 → 14:32, 90 → 01:30”처럼 입력 방식을 설명한다. “저장값은 정수 초로 변환됩니다” 같은 구현 설명은 사용자 안내에서 제거한다.
- 시간 오류를 해당 필드에 연결하고 수정 시 오래된 오류가 새 오류를 덮지 않게 한다.
- 최신 서버 런타임을 사용하는 기존 계약을 유지한다. 서버 조회 실패와 메타데이터 자체의 길이 없음은 구분한다. URL의 duration을 신뢰하지 않는다.
- 순수 parser뿐 아니라 UI의 입력→blur→저장 변환에 쓰이는 순수 로직을 테스트한다. React Native 컴포넌트를 `node:test`에 import하지 마라.

## 6. P1 — 실제 터치 영역과 접근성

대상: 공통 UI, 카드, `TagChip`, 검색 필터, 인증 링크, 핀 취소·감정·태그 조작.

1. 최소 실제 터치 영역 44×44를 확보한다. 주요 버튼은 48 이상을 기본 제안으로 삼고, 아이콘의 시각적 크기는 그대로 둘 수 있다.
2. 현재 32×32인 카드 핀 버튼, 폼 취소, 작은 검색 칩, 인증 보조 링크, 태그 삭제를 우선 수정한다.
3. `hitSlop`만 크게 설정해서 인접 영역이 겹치거나 부모 경계를 넘지 못하는 문제가 생기지 않게 한다. 기존 진행 증감 버튼의 40+hitSlop 4는 이미 확대 영역이 있다는 사실을 반영한다.
4. 반복되는 버튼은 “작품명 핀 추가”, “3화 시청 완료”, “태그명 삭제”처럼 대상을 알 수 있게 한다. selected/checked/disabled/busy/expanded 상태와 첫 오류를 전달한다.
5. 필터/진행 모달은 열릴 때 내부로 포커스를 옮기고, 닫히면 실행 버튼으로 복원한다. 배경으로 포커스가 빠지는지 웹과 스크린 리더에서 확인한다.

## 7. P1 — 핀 작성, 이탈 방지, 상세 읽기

대상: `PinComposer`, 핀 생성/상세 라우트와 기존 컨텍스트 조회.

1. 작성 상단에 작품명·시즌/회차 또는 영화·시간 정보를 보여라. 표시 정보는 신뢰할 수 있는 조회 데이터로 확인하고, route 표시 문자열만으로 저장 대상을 정하지 마라.
2. 시간·메모를 먼저 보여주고 메모 500자 카운터와 태그 20자/10개 안내를 제공한다. 제한 초과/중복 태그를 추가할 수 없는 이유를 설명한다.
3. 태그·감정은 접을 수 있는 보조 영역으로 구성 가능하지만, 접었다 펴도 입력이 보존되어야 한다. 스포일러 설정은 계속 쉽게 찾을 수 있어야 한다.
4. dirty 판단에는 시간·메모·태그·감정·스포일러와 아직 추가하지 않은 태그 입력을 포함한다. 취소, 헤더 뒤로, Android 뒤로, iOS 이탈 제스처를 통합 처리한다. 변경이 있을 때만 “계속 작성/버리기”를 묻는다.
5. 저장 중 이탈과 중복 요청을 제어한다. 실패하면 폼을 보존하고 재시도를 제공한다. 성공 후에는 이탈 확인이 다시 뜨지 않도록 한다. 앱 종료 후 영구 draft 복구까지 범위를 넓히지 마라.
6. 핀 상세 읽기 화면에 작품·시즌/회차·시간·태그·감정을 표시하고 긴 메모를 스크롤로 읽게 한다. 편집·뒤로는 마지막까지 접근 가능해야 한다.
7. 스포일러는 opacity로만 숨기지 말고 보기 전 원문이 시각/접근성 트리에 없도록 한다. 기존 공유 캡처용 숨김 뷰도 검사한다. 화면 이탈 후 재진입하면 다시 가린다.
8. 핀 삭제 등 위험 작업은 주요 저장 동작과 구분하고 기존 확인·캐시 복구 계약을 유지한다.

## 8. P1 — 기록을 먼저 보여주는 홈·상세

대상: `app/(tabs)/index.tsx`, `app/content/[id].tsx`, 관련 카드.

1. 모바일 홈의 보는 중 3열을 단일 열 요약 카드로 바꾼다. 작품명·시즌·진행 요약·다음 행동을 우선한다. 라이브러리의 명시적 2열 갤러리까지 일괄 단일 열로 바꾸지 마라.
2. 기록이 있으면 최근 기록/보는 중/최근 핀을 검색 hero보다 먼저 보여준다. 기록이 없을 때 검색으로 첫 작품 추가를 안내한다.
3. 콘텐츠 상세의 모바일 포스터 높이를 줄이고, 제목·내 기록 요약·주요 CTA를 줄거리/인물/리뷰보다 앞에 놓는다. 긴 줄거리는 더보기로 펼친다.
4. 시리즈는 명확한 회차 선택으로, 영화는 바로 핀 작성으로 연결한다. 일반적인 시리즈 카드의 핀 추가가 episode 없는 작성 화면으로 가지 않게 한다.
5. `focus=progress`와 라이브러리의 직접 진행 위치 편집을 유지한다. 저장 동작을 줄이려는 목적으로 값 입력 즉시 mutation하거나 감상 상태를 자동 전환하지 않는다.
6. 11번 MVP에서 제외된 추천·인물·리뷰·공유·가져오기는 MVP UI와 불필요한 조회 호출에서 가드한다. DB나 사용자 기록을 삭제하지 마라. 기존 상태 데이터의 의미 변경은 별도 결정 사항으로 보고한다.

## 9. P2 — 검색 필터와 복귀 동작

대상: `app/search.tsx`, `ContentSearchBar`, 라이브러리 필터 시트의 재사용 가능한 패턴.

1. 모바일 검색 필터를 적용형 하단 시트로 통일한다. 외형/접근성 패턴을 재사용하되 검색과 라이브러리의 서로 다른 필터 도메인을 억지로 하나로 합치지 마라.
2. 시트에서는 draft만 바꾸고 적용 시 한 번 반영한다. 취소하면 기존 필터를 유지하고 초기화 의미를 명확하게 한다. 필터 개수를 검색창 옆에 표시한다.
3. 명시적으로 검색을 시작하는 진입에서만 필요한 자동 포커스를 제공한다. 검색 결과에서 상세를 보고 돌아오면 입력·필터·스크롤을 복원하고 키보드를 불필요하게 열지 마라.
4. 기존 2자 검색 조건, 다음 페이지 로딩/실패 재시도, 캐시 결과, 한국어 시즌 검색과 시즌별 등록 배지를 유지한다. 외부 API 어댑터를 재작성하지 마라.

## 10. 진행 순서와 검증

1. 최신 코드와 `git status`를 확인해 재현 가능한 결함/이미 해결/추가 실기기 확인을 구분한다.
2. P0 메뉴·돌아가기·Safe Area → 시간 원문 보존 → 키보드 대응 순으로 작업한다.
3. P1 터치 영역 → 핀 작성/읽기/이탈 → 홈·상세 동선 순으로 작업한다.
4. P2 검색 필터와 복귀를 정리한다.
5. `docs/19_mobile_usability_spec.md` §8의 **MU-01~MU-28 전체 행**을 검증 항목으로 옮겨라. 기능 로직은 순수 함수 테스트, UI 동작은 실제 UI 검증으로 매핑한다. 스타일 객체의 숫자만 확인하는 테스트로 실측을 대체하지 마라.
6. 기존 명세의 테스트 표와 회귀 테스트를 삭제·축소하지 마라. 진행률·시즌·시간·스포일러·핀 캐시의 기존 계약을 함께 확인한다.
7. `npm test`, `npm run typecheck`, `npm run lint`를 실행한다. 변경 관련 실패를 수정하고 기존 실패는 구분해서 보고한다.
8. 웹은 320×568/360×800/390×844/430×932/844×390, breakpoint는 767/768/1199/1200을 확인한다. 네이티브는 iOS/Android의 세로 화면·키보드·Safe Area·스크린 리더·큰 글자를 확인한다.
9. 목록 200화, 긴 한국어 제목, 메모 500자, 여러 시즌, 포스터 없음, 로딩/빈 결과/실패/오프라인을 확인한다. 웹 검증을 네이티브 검증 완료로 보고하지 마라.
10. Expo 웹 서버는 기존 8081을 먼저 확인한다. 필요할 때만 `npm run web -- --port 8081 --localhost --clear`를 사용한다. 다른 포트로 우회하지 마라.

로그인이나 실기기 접근이 불가능하면 해당 UI 검증을 미검증으로 남기고 가능한 구현·자동 검증을 완료해라. 실제 계정 기록을 검증 목적으로 임의 변경하지 마라. 실행하지 않은 테스트를 통과로 표시하지 마라.

## 11. 완료 보고 형식

- 무엇이 어떻게 편해졌는지 핵심 변경을 설명한다.
- M-01~M-11 각각의 처리 여부와 주요 변경 파일을 제시한다.
- 가능한 경우 같은 화면 크기의 변경 전/후 화면을 제공한다.
- MU-01~MU-28 및 기존 관련 테스트의 통과/실패/미검증 상태와 이유를 제공한다.
- `npm test`, 타입 검사, 린트의 실제 결과와 남은 제한을 적는다.
- 기존 D-N 결정을 바꾸어야만 해결 가능한 항목은 근거와 함께 별도로 보고한다.
